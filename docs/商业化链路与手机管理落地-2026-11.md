# 商业化链路与手机管理落地（2026-11）

> 一句话：先在电脑上立起一台「收银机 + 门禁」——账号、钱包、token 计量、模型代理；再让手机用同一个账号连回自己的电脑，管理 OpenFuture 的项目和会话。

本文对应代码：`cloud/`（Java 17 + Spring Boot 3.3.5，端口 8090）。
配套文档：`docs/安卓端远程管理调研与适配-2026-11.md`（手机端方案对比与协议草案）。

---

## 1. 你现在拥有了什么

原来只有一个桌面应用（OpenFuture）。现在多了三样东西：

| 东西 | 在哪 | 作用 | 状态 |
| --- | --- | --- | --- |
| 电脑端 OpenFuture | `D:\OpenFuture` | 你平时写代码、跑 Agent 的地方 | 已有 |
| 云端账号平台 | `D:\OpenFuture\cloud` | 管账号、设备、钱包、充值、token 用量、模型转发、后台 | **本次已建好并跑通** |
| 手机端 App | 已出 APK（WebView 壳 + 局域网直连） | 在外面看项目、看会话、发消息、批审批 | 已完成 M1–M3，见《[手机管理 OpenFuture](手机管理OpenFuture-使用说明-2026-11.md)》 |

用一张图表示三者关系：

```
┌────────────┐   登录/充值/看用量     ┌──────────────────┐
│  手机 App   │ ───────────────────▶ │  云端账号平台      │
│            │                       │  Java, :8090      │
│            │   配对后直连（局域网）  │  账号/钱包/计量    │
│            │ ──────────────┐       └──────────────────┘
└────────────┘               │                 ▲
                             ▼                 │ 模型调用走 /v1 并扣费
                    ┌──────────────────┐       │
                    │ 电脑端 OpenFuture │───────┘
                    │ 项目/会话/Agent   │
                    └──────────────────┘
```

关键点：**手机要看的项目、会话数据在电脑上，不在云平台**。云平台只负责「你是谁、还有多少钱、这次调用花了多少」。所以手机端要分两路连接：一路找云平台验身份，一路找电脑拿数据。

## 2. 用大白话解释这台「账号平台」

把它想成一栋写字楼：

- **门禁** = 注册/登录（手机号 + 密码，短信验证码）。进门发一张临时门卡（JWT 令牌），之后每次进门刷卡。
- **前台登记** = 设备配对。电脑上生成一个 6 位数字（5 分钟内有效），手机上输入，两台设备就登记到同一个账号名下。以后手机能看到「我的电脑」。
- **电表** = token 计量。谁用了多少电（输入/输出 token），按价目表扣钱，写进流水账。
- **钱包** = 余额。充钱、兑换码、扣费都在这里加减，任何一笔都有流水。
- **总闸** = 余额不足就拒绝服务（HTTP 402），不会让你欠费跑模型。
- **模型代理** = 你给电脑端配的是平台发的 `sk-of-...` 密钥，不是真的 OpenAI/DeepSeek key。平台拿自己的上游 key 去调模型，再按用量扣你的钱包。上游 key 不会下发到任何客户端。
- **管理后台** = 老板看的账本：多少用户、多少设备、收入多少、今天消耗多少、价格表、生成兑换码。

金额单位在代码里叫「微元」：**1 元 = 1,000,000 微元**，1 分 = 10,000 微元。这样做是为了 token 单价很小时不丢精度。

## 4. 怎么把它跑起来

### 4.1 环境

- JDK 17（你机器上系统默认是 Java 8，不能用）。可用 IntelliJ 自带的：
  `F:\PROGRAM_files\ideaIU-2023.3.2.win\jbr`
- Maven 3.9+。系统里的 3.6.1 太旧，且全局 `settings.xml` 指向一个没启动的 Nexus（`localhost:8081`），会构建失败。用 IDEA 自带的 Maven：
  `F:\PROGRAM_files\ideaIU-2023.3.2.win\plugins\maven\lib\maven3`
- 构建时用项目内镜像配置 `cloud/maven-settings.xml`（阿里云 HTTPS），绕开坏掉的全局镜像。

### 4.2 构建与启动

```bat
cd D:\OpenFuture\cloud
build.cmd -DskipTests package    :: 用 IDEA 自带 Maven 3.9.5 + JDK 17 构建
run.cmd                          :: 启动，监听 8090
```

两个 `.cmd` 已把 `JAVA_HOME`、Maven 路径和镜像配置固定好，双击也能用。等价的手动命令：

```bat
set JAVA_HOME=F:\PROGRAM_files\ideaIU-2023.3.2.win\jbr
set MAVEN_HOME=F:\PROGRAM_files\ideaIU-2023.3.2.win\plugins\maven\lib\maven3
"%MAVEN_HOME%\bin\mvn" -s maven-settings.xml -DskipTests package
"%JAVA_HOME%\bin\java" -jar target\openfuture-cloud.jar
```

启动后：

- 接口根地址：`http://127.0.0.1:8090`
- 手机账户页：`http://<电脑IP>:8090/app.html`（手机浏览器直接打开，登录后可看余额/用量/设备/密钥/充值；后续用 Capacitor 包成 APK）
- 管理后台页面：`http://127.0.0.1:8090/admin.html`（令牌默认 `dev-admin`）
- H2 数据库：`cloud/data/openfuture.mv.db`（文件库，重启不丢）
- 首次启动自动灌入 4 个模型价格和 1 个 100 元演示兑换码

### 4.3 默认口令（**上线前必须改**）

| 配置 | 默认值 | 环境变量 |
| --- | --- | --- |
| JWT 签名密钥 | `openfuture-dev-jwt-secret-...` | `OF_JWT_SECRET`（≥32 字节） |
| 管理员令牌 | `dev-admin` | `OF_ADMIN_TOKEN` |
| 支付回调签名密钥 | `dev-pay-secret` | `OF_PAY_SECRET` |
| 短信验证码 | 固定 `123456`（开发模式） | `OF_DEV_SMS=false` 关闭 |
| 模拟支付 | 开启 | `OF_PAY_DEV_MODE=false` 关闭 |
| 上游模型 | 空 = 演示回声 | `OF_UPSTREAM_BASE_URL`、`OF_UPSTREAM_API_KEY` |

### 4.4 接真实模型

```bash
set OF_UPSTREAM_BASE_URL=https://api.deepseek.com/v1
set OF_UPSTREAM_API_KEY=sk-你的真实key
"%JAVA_HOME%\bin\java" -jar target\openfuture-cloud.jar
```

然后在电脑端 OpenFuture 的模型设置里填：

- Base URL：`http://127.0.0.1:8090/v1`（手机/其他电脑访问则用本机局域网 IP）
- API Key：后台「钱包 → 创建密钥」得到的 `sk-of-...`
- 模型名：`deepseek-chat` / `gpt-4o-mini` / `claude-sonnet-4`（以后台价格表为准）

## 5. 手机管理电脑上的 OpenFuture（重点）

### 5.1 为什么不能只靠云平台

云平台知道你「是谁、有多少钱」，但不知道你电脑上有哪些项目、哪个会话聊到哪了。这些数据在电脑本地（`projects.json` + Pi 会话文件 + 记忆库），**不能也不该整份上云**。所以：

- 手机 → 云平台：登录、看余额、看用量、设备列表；
- 手机 → 电脑：配对后直连，拿项目/会话、发消息、批审批。

### 5.2 架构（自用阶段）

```
手机 App ──① 登录拿 JWT──▶ 云平台
   │
   └──② 配对拿「电脑地址 + 一次性凭证」──▶ 电脑端内置的 RemoteHost
                                             （Electron 主进程，127.0.0.1:19744 或局域网 IP）
```

电脑端已经有现成的雏形：`parallel/multiagent/src/desktop/server.ts`（HTTP + SSE，默认 `127.0.0.1:19744` + token，8 项合同测试）。把它搬进 Electron 主进程即可，不用从零写。

### 5.3 配对流程（用户视角，只有 3 步）

1. 电脑端点「手机连接」→ 屏幕出现二维码 + 6 位配对码（5 分钟有效）；
2. 手机 App 登录同一账号 → 扫码或输入 6 位码；
3. 配对成功，手机首页出现「我的电脑」，点进去就是项目列表。

配对码在云平台侧校验（`/api/devices/pair-code`、`/api/devices/pair`），保证只有同一账号能绑。

### 5.4 网络三档（按你的使用场景选）

| 场景 | 方案 | 成本 | 说明 |
| --- | --- | --- | --- |
| 手机和电脑同一 Wi-Fi | 局域网直连 `http://电脑IP:19744` | 0 | 最快，自用首选；需放行 Windows 防火墙 |
| 在外面（4G/5G） | Tailscale / ZeroTier 组虚拟局域网 | 免费 | 装一次，之后像在同一局域网；无需公网 IP |
| 给家人/团队用 | 自建中转 relay | 一台小服务器 | 手机和电脑都主动外连，不暴露家里 IP |

不要一上来就做公网端口映射：家宽 IP 会变，且直接暴露服务风险高。

### 5.5 手机上具体能做什么

**现在已经能用（账号与计费部分）**

手机浏览器打开 `http://<电脑IP>:8090/app.html`，用手机号登录后可以：

- 看余额、今日消耗、近 7 天用量明细
- 看设备列表并吊销、生成/填写配对码
- 新建 `sk-of-…` 密钥（只显示一次）、吊销旧密钥
- 兑换充值码、下演示订单并模拟支付、查看流水

这一页就是将来 APK 里嵌的同一个页面（Capacitor 包壳后即可安装），所以先把网页版跑通，再打包不会返工。

**已完成（2026-11-16，M1–M3）**

电脑端 `src/main/remote-host.ts` 提供局域网 HTTP + SSE 服务（默认 8787），手机页 `mobile/index.html` 与桌面端共用同一套 IPC 校验；APK 在 `mobile/android/OpenFuture-phone.apk`。装上后可以：

- 项目列表、最近会话、会话历史（只读 + 继续聊）
- 发消息、看流式回复、停止生成
- 审批卡片（工具调用需要确认时，手机上点「允许/拒绝」）
- 余额/用量小卡片（来自云平台，已具备，下一步接进手机页）

使用步骤、安全边界与排错见《[手机管理 OpenFuture 使用说明](手机管理OpenFuture-使用说明-2026-11.md)》。

**第二版（P1）**

- 文件树与 diff 查看、记忆库搜索（只读）
- 群聊只读、任务/自动化状态
- 推送通知（审批待办、任务完成）

**不做**：手机上装依赖、跑终端、改系统设置。这些留在电脑上。

### 5.6 协议草案（自用版足够）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/v1/health` | 电脑端存活、版本、协议版本 |
| POST | `/v1/pair/claim` | 用配对码换设备令牌 |
| GET | `/v1/projects` | 项目列表 |
| GET | `/v1/sessions?projectId=` | 会话列表 |
| GET | `/v1/sessions/{id}/messages?since=seq` | 历史消息（增量） |
| POST | `/v1/sessions/{id}/messages` | 发消息 |
| POST | `/v1/sessions/{id}/stop` | 停止生成 |
| POST | `/v1/approvals/{id}` | 允许/拒绝 |
| WS | `/v1/events?since=seq` | 流式事件（断线用 `since` 补发） |

所有请求带 `Authorization: Bearer <设备令牌>`；事件带自增 `seq`，断线重连不丢消息。

### 5.7 账号体系与扫码登录（2026-11 新增）

- **电脑端入口**：左下角头像不再直接打开设置，而是「我的账户」面板：账号密码登录、手机扫码登录、余额与充值、管理后台入口、已登录设备列表；设置仍从原齿轮进入。
- **扫码登录**：电脑点「手机扫码」→ 云端生成一次性票据（ticket 32 位十六进制 + 6 位确认码 + 轮询密钥，120 秒有效）→ 二维码内容是 `openfuture://qr?t=...&b=...`；手机扫码唤起 App 或手填 6 位码确认；电脑每 1.6 秒轮询，确认后直接拿到登录令牌，全程不输密码。
- **安全约束**：票据一次有效、过期即作废；轮询必须带 `pollSecret`；只有已登录的账号才能认领票据；重复认领返回 409。
- **管理端**：用户封禁/解封、人工调整余额（记 ADJUST 流水）、订单按状态筛选、兑换码列表。
- **每小时维护**：`Housekeeping` 定时任务自动关闭 30 分钟未支付订单、清理过期登录票据与配对码；间隔用 `openfuture.housekeeping.interval-ms` 配置（默认 3600000 毫秒）。

## 6. 商业化链路：钱从哪来、怎么扣、怎么对账

### 6.1 三道闸

```
请求进来
  │
  ├─ 闸一：密钥有效吗？        → 401，拒绝
  ├─ 闸二：余额够吗？          → 402，提示充值
  └─ 闸三：调用完成后按 token 扣费 → 写 usage_record + ledger_entry
```

三道闸都在服务端，客户端改不了价格，也绕不过扣费。

### 6.2 收入模型（从简单到复杂）

1. **token 差价**（最先做）：上游成本 X 元/百万 token，售价 X×1.3～2。后台价格表随时改。
2. **套餐包**：9.9 元 100 万 token、29.9 元包月等。当前用「充值 + 按量扣」即可模拟，套餐是价格表的一个变种。
3. **设备数/席位**：免费 1 台设备，多设备或团队协作收费。设备表已支持吊销。
4. **私有部署**：把 `cloud/` 打包卖给有内网需求的团队（一次性授权费）。

### 6.3 支付现状（诚实说明）

现在只有**开发模式模拟支付**：下单后调 `/api/orders/{orderNo}/dev-pay` 直接到账。这适合自用和演示，**不能收真钱**。

接真钱有三条路：

| 方式 | 门槛 | 适合 |
| --- | --- | --- |
| 支付宝当面付 / 微信 Native 支付 | 需营业执照或个体户 | 正经做生意 |
| 聚合支付服务商 | 需资质，有费率 | 想省对接 |
| 兑换码/卡密（发卡平台） | 最低 | 自用、小范围、内测 |

**不要用个人收款码做自动到账**：没有回调、无法对账、风控会封，也不合规。

支付回调已经写好验签和幂等（`/api/pay/notify`，签名 = HMAC-SHA256(密钥, 订单号|金额|状态)），接真实渠道时只需把渠道回调转成这个格式。

### 6.4 合规提醒（不是吓唬，是真实成本）

- 面向公众提供生成式 AI 服务，需要做**生成式人工智能服务备案**（算法备案 + 安全评估），个人自用不涉及。
- 收费经营网站/App 通常需要 **ICP 备案**；涉及在线支付的，支付机构还会审资质。
- 短信验证码需要短信服务商资质和签名报备；自用阶段可以先用邮箱/固定码，或干脆只做本机登录。
- 用户数据（手机号、对话）要能导出/删除；不要把用户对话拿去训练。

自用阶段：以上都可以先不办，但**别公开卖**。

### 6.5 后台怎么对账

`http://127.0.0.1:8090/admin.html`：

- 总览：用户数、设备数、已支付订单、累计收入、今日请求数、今日消耗、未使用兑换码
- 用户表：余额、注册时间
- 订单表：订单号、金额、渠道、状态
- 价格表：改单价立即生效
- 生成兑换码：面额 + 数量 + 前缀，明文只显示一次

每一笔加减钱都有 `ledger_entry` 流水（ORDER/REDEEM/USAGE/REFUND），可以逐笔核对。

## 9. 常见问题

**Q：我只自己用，也要搞账号平台吗？**
A：平台的价值是「一个账号管所有设备 + 用量有账」。只自己用可以简化成单账号，但代码已经写好了，跑起来不费事；以后想给家人/同事用不用重写。

**Q：手机必须和电脑在同一个 Wi-Fi 吗？**
A：自用第一版是。要在外面用，装 Tailscale（免费）即可，不用公网 IP。

**Q：平台会不会看到我的代码和对话？**
A：项目/会话数据只在电脑和手机之间传，不经过云平台。只有模型调用经过平台（不然没法计量），平台能看到请求内容——所以别把平台部署到不信任的机器上；自用就部署在自己电脑。

**Q：API key 会不会泄露？**
A：平台只存 key 的 SHA-256 哈希，明文只在创建时显示一次；上游 key 只在服务端环境变量里。

**Q：断网了怎么办？**
A：手机端只影响远程查看；电脑端 OpenFuture 本身照常工作。WS 事件带 `seq`，恢复后从断点补发。

**Q：能不能不打包 APK，先用网页？**
A：可以，而且建议先这样。手机浏览器打开电脑的页面即可；体验稳定后再用 Capacitor 包成 APK，成本低很多。

| POST | `/api/redeem` | 兑换码 |

| GET | `/api/pay/checkout?orderNo=` | 收银台信息 |
