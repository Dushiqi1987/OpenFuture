## 2. 实现

### 2.1 公共协议

`src/shared/protocol.ts`：

- `MemorySearchEngine = 'fts5' | 'qmd' | 'wiki'`。
- `MemoryWikiEngine = 'off' | 'mcp'`。
- `MemoryWorkspaceState.wikiEngine`。
- `MemorySearchResult.engine/engineNote/wikiEngine/wikiNote`。
- `MemorySearchHit.engine`。

### 2.2 QMD 词法适配

`src/memory-host/index.ts`：

- `OPENFUTURE_QMD_MODULE` 指向 QMD 的 ESM 入口；未设置时完全使用 FTS5。
- `syncQmdCorpus` 只导出 active source 的 active evidence，写为 `memory/qmd/<workspaceId>/corpus/ev-<id>.md`，并删除不再 active 的文件。
- `searchQmd` 懒加载模块、更新索引、调用 `searchLex`，再用 evidence id 回表，二次校验 active 状态。
- QMD 失败时返回 `{ ok:false }`，`searchMemory` 保留 FTS5 命中并写入 `engineNote`。
- `memoryState.searchEngine` 在配置模块时显示 `qmd`；实际失败会通过 `engineNote` 说明。

### 2.3 pi-llm-wiki MCP 适配

- `OPENFUTURE_WIKI_MCP` 指向 `dist/mcp/index.js`，`OPENFUTURE_WIKI_ROOT` 指向 wiki vault。
- `startWikiClient` 使用 `process.execPath` + `ELECTRON_RUN_AS_NODE=1` 启动 stdio MCP，按行 JSON-RPC：
  - `initialize`（protocolVersion `2025-06-18`）→ `notifications/initialized`；
  - `tools/call` 调用 `wiki_recall`，从返回文本中截取 JSON 数组；
  - 超时 10 秒；退出/错误时拒绝所有 pending，下一次搜索重新建连。
- 命中映射为 `id='llm-wiki:<raw>'`、`kind='wiki'`、`engine='wiki'`，引用取 `path`，摘要取 `preview`。
- MCP 不可用时只清空 Wiki 命中，保留 FTS5/QMD 结果，并写入 `wikiNote`。
- `memoryState.wikiEngine` 显示 `mcp` 表示已配置；未配置为 `off`。

### 2.4 UI

`src/renderer/src/MemoryPanel.tsx`：

- 搜索结果提示显示 `检索引擎：QMD/FTS5 · Wiki 引擎：pi-llm-wiki/未配置`。
- 显示 `engineNote` / `wikiNote` 回退原因。
- 结果 badge 使用 hit.engine，Wiki 命中显示 `wiki`。

## 3. 实测

### 3.1 开发版 QMD（隔离用户目录 `.scratch/p4q-userdata`，CDP 9244）

启动环境：

```text
OPENFUTURE_QMD_MODULE=D:/OpenFuture/.scratch/p1-upstream/qmd/node_modules/@tobilu/qmd/dist/index.js
```

- `memoryState`：workspaceId `43994f88801f3464b089b4f8`，`searchEngine:'qmd'`。
- 导入会话证据后 `memorySearch('SESSION_EVIDENCE_BASE')` 命中 evidence，`engine:'qmd'`、`hit.engine:'qmd'`，score `9.99999000001e-7`。
- 中文查询 `测试` 也命中，score `0.0000018333299722283844`。
- 源文件与索引存在：`.../memory/qmd/43994f88801f3464b089b4f8/corpus/ev-23b8a738-3607-4de6-88f6-015688c3c7ac.md`（307 字节）、`index.sqlite`。
- 撤销 source `src-2a367625-9be0-4570-ab4b-e2257e74cba9` 后同一查询 `hits:[]`，`engine:'qmd'`，撤销过滤生效。

### 3.2 开发版 FTS5 回退

- 不带 `OPENFUTURE_QMD_MODULE` 启动同一 userData。
- `memoryState.searchEngine:'fts5'`，`memorySearch('SESSION_EVIDENCE_BASE')` 命中，`engine:'fts5'`、`hit.engine:'fts5'`。

### 3.3 Wiki MCP（开发版与打包版均验证）

启动环境：

```text
OPENFUTURE_WIKI_MCP=D:/OpenFuture/.scratch/p1-upstream/wiki/node_modules/.pnpm/@zosmaai+pi-llm-wiki@0.12.5_331d0c4efd9acd3116edb82deb053b76/node_modules/@zosmaai/pi-llm-wiki/dist/mcp/index.js
OPENFUTURE_WIKI_ROOT=D:/OpenFuture/.scratch/p1-upstream/wiki/vault 中文 空间
```

- 直接 MCP 探针 `wiki_recall({query:'记忆设计'})` 返回数组，元素含 `id/title/type/preview/path/score`。
- 应用内 `memorySearch('记忆设计')` 返回：
  - `id:'llm-wiki:sources/SRC-2026-11-08-001'`
  - `kind:'wiki'`
  - `title:'OpenFuture 记忆验收来源'`
  - `engine:'wiki'`
  - `score:22.8`
  - `excerpt` 为 `preview` 文本。
- `memoryState`：`searchEngine:'qmd'`、`wikiEngine:'mcp'`。
- Wiki 模式下 `memorySearch` 只返回 Wiki 命中；RAG/组合模式保留 evidence 命中（`rag` 的既有语义包含 wiki 类型）。

### 3.4 Wiki 失败回退

- 将 `OPENFUTURE_WIKI_MCP` 指向不存在的文件启动打包版。
- `memoryState.wikiEngine:'mcp'`，但 `memorySearch` 返回 `wikiNote`：
  `pi-llm-wiki 暂不可用：Wiki MCP 已退出（1）：... Node.js v24.22.2`
- 同一查询的 QMD evidence 命中仍返回；Wiki 命中为空；应用不崩溃。

### 3.5 打包版

`release/p3.3-qmd-wiki-runnable/OpenFuture.exe`（CDP 9244，隔离 userData）重复 3.3：QMD evidence 命中 `ev-fb3d9edc-6a55-412e-bb30-85ba1cfdf35f`，Wiki 命中 `llm-wiki:sources/SRC-2026-11-08-001`，`engine:'qmd'`、`wikiEngine:'mcp'`，证明打包后的 MCP 子进程与 QMD 动态加载均可用。

## 4. 限制与后续

- QMD 2.8.3 与 pi-llm-wiki 0.12.5 仍作为外部可选资源，不默认复制进安装包；用户需自备路径。后续可做可选的“资源目录”安装向导。
- QMD 只使用 `searchLex` 词法检索；`node-llama-cpp` 向量能力未接入。
- Wiki 只读 `wiki_recall` 的 preview，不调用 `wiki_ingest`，不自动生成/发布 Wiki 页面。
- 每次 QMD 搜索都会 `update()` 索引；数据量大时需要增量/节流策略。
- `wikiEngine:'mcp'` 只表示已配置，不表示 MCP 健康；实际失败通过 `wikiNote` 暴露。
- 系统提示注入纠正正文的独立 mock 复验仍待补（P3.2 遗留项）。
