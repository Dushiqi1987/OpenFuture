# OpenFuture 多 Agent 协作 · Super-Agent 设计

2026-11-09 · v0.4 独立开发线 · Windows 桌面端

在既有 Pi 单 Agent 上增加「团队模式」。一个 Super-Agent 理解需求、拆分任务、选择助手和调度依赖；多个 Pi 子 Agent 各自在独立会话工作。助手可通过受控收件箱沟通。测试与集成助手负责在独立集成副本拼装、测试和提交验收证据，Super-Agent 汇总给用户。

## 2. 用户交互与意图识别

1. 项目对话保留「单 Agent」作为默认。在输入框可选择「团队」，打开任务板可查看计划、依赖和预计角色。用户可以编辑角色或移除任务。普通多问也可交给同一助手一次回答；只有相对独立、角色差异明确或需要并行的工作才拆为子任务。
2. Super-Agent 输出可校验计划，字段包含主目标、意图列表、任务 ID、角色模板、输入产物、依赖、验收条件、建议记忆视图和允许写入范围。意图区分问题回答、检索、分析、前端、后端、测试集成等。含文件改动和外发资料的操作沿用项目现有权限；范围变更需要相应授权。
3. 运行时检查 DAG 无环、角色和 ID 有效、权限可收敛、写路径不重叠及预算足够。低置信度或不清楚边界时询问用户或展示待确认计划。规划超时或结构不合法时，保留用户草稿并提供单 Agent 路径。每个原始问题要能追到任务或最终答复。
4. 任务板显示等待、运行、需要协作、测试失败、待集成和完成。子 Agent 的身份、模型、预算、记忆视图、最近消息和交付物可查看。用户能停止整个运行，也能取消单项并看到下游影响。

## 3. 角色与记忆

「个人信息设定」采用可审查的角色卡。角色卡字段为显示名、专长、职责、沟通语言、输出契约、可用工具、写入范围、模型配置、记忆视图和预算。角色卡描述工作方式，权限由运行时单独核定。

| 角色 | 责任与交付 | 记忆与访问 |
|---|---|---|
| 研究助手 | 根据需求搜索公开资料，返回出处、关键结论、可信度和未知项 | 只读。可读取本项目授权 RAG 资料或发布 Wiki。对外发送的查询默认只包含必要关键词 |
| 后端助手 | 实现服务与存储，先交接口合同及样例，再交代码差异、迁移和测试 | 仅写自己的副本与授权目录。可读项目技术 Wiki 或必要的 RAG 资料 |
| 前端助手 | 基于接口合同实现界面与交互，交页面差异和测试证据 | 仅写自己的副本与授权目录。可用固定 API 合同和模拟服务提前工作 |
| 测试与集成助手 | 根据计划与证据复核产物、串行试合、运行构建和回归、报告通过项和阻塞项 | 仅能写独立集成副本；读各任务交付。最终合入主线走项目的授权入口 |

有效记忆范围是项目权限与角色请求的交集。任务运行中，子 Agent 可按角色采用关闭、RAG 或发布 Wiki 的只读视图；Dreaming 作为项目级后台治理，子 Agent 可以在授权下读取经批准的 L3 或提出待审记忆候选。子 Agent 的对话、推理和工具结果保存在各自会话。任何跨项目、未发布、已撤销或角色权限外的数据在读取和出站前过滤。产物和消息只共享完成当前依赖所需的内容。

## 4. 运行时和助手间通信

- **Super-Agent** 负责意图、计划、冲突升级和最终总结。**调度器**校验任务图、分配并发槽、固定任务身份、处理超时和取消。**PiTaskRunner** 为每个子任务分配独立 Pi session 与上下文，复用已有模型和工具适配。每个运行都携带 `projectId, runId, taskId, agentId, attempt, baseRevision`，避免共享可变当前会话状态。
- 任务先持久化再执行。基本状态为 `planned → ready → running → needs_input / succeeded / failed / cancelled`；写代码的任务另有 `reviewed → integrated`。记录 attempt 和递增事件序号，崩溃后标记中断并重新核对产物。幂等重试使用同一任务 ID 和新 attempt，已有差异必须核对基线。首版最多三路 worker 并行，按服务商限流退避。只有运行时可以生成新的任务 ID，子助手通过请求提出追加任务。
- **受控本地收件箱**采用 `send / inbox / reply / status`。消息含项目、运行、发送方、接收方、关联任务、`correlationId`、类型、简短正文和产物引用。类型包括 `request`、`reply`、`contract`、`artifact`、`blocker` 和 `review`。身份由运行时赋值，只允许同项目同运行的授权收件人。发送落库后确认，消费按 ID 去重；恢复后可重放未确认事件。
- 可等待答复，但等待状态释放执行槽，避免三路都占着并发槽时研究助手无法启动。每个请求有时限，支持取消与超时后升级给 Super-Agent。新增依赖需重新查环。消息是任务数据，不能授予新工具权限或扩大目录；角色与权限由受信配置决定。
- 交付使用不可变产物引用及哈希。典型链路是后端发布 OpenAPI／类型合同，前端消费同一版本先对 mock 开发；若后端需要查资料，就给研究助手发请求，研究助手回复带出处的报告；合同变更通知前端和测试，受影响的验收需重跑。Super-Agent 只把经过校验的必要结果带进最终回答。

## 5. 并行写入与测试合入

- 每个写代码的子任务使用独立 Git worktree 或独立副本。主线没有 Git 时用可校验基线清单和独立副本。每个任务有自己的构建目录、缓存、测试端口和临时数据，禁止共享有写权限的用户目录与真实凭证。
- 任务图分配唯一文件所有者。共享合同、协议、数据库 schema 和根锁文件只能由指定任务修改。前端与后端通过版本化合同协作。若需要触碰同一文件，暂停相关提交并由 Super-Agent 指定唯一写入者，其他助手发送建议差异。
- 测试与集成助手先检查基线、文件白名单、哈希和依赖，再在集成副本逐项应用差异，做冲突检查、构建、静态检查、独立和端到端测试。失败退回责任人修复；清单缺失或冲突时不标完成。最终给出可审查差异、可运行 EXE、测试证据和剩余项。主线写入由显式授权的集成步骤执行。

## 6. 本开发线交付顺序

| 阶段 | 交付 |
|---|---|
| M0 · 原型 | 不修改主线。在独立副本实现有类型的任务图、角色卡、并发调度、内存或 SQLite 邮箱以及模拟 Pi worker。证明一个多意图请求可分给研究、后端、前端与测试 |
| M1 · Pi 适配 | 在副本内接真实 Pi 子会话生命周期，使用本地模拟端点验证并行流式、失败、取消、工具范围、跨角色消息和断点恢复 |
| M2 · 桌面集成契约 | 交接任务板事件、项目级记忆视图、版本化产物与测试整合接口。主线团队审查后再接 UI、项目和模型中心 |

独立验收至少覆盖以下情况。

- 单问题保持单 Agent 路径，多问题可追溯到任务。角色请求与项目权限冲突时拒绝或裁减。
- 研究与后端独立并行，前端在合同后开始或用 mock 提前工作，测试在前后端产物就绪后启动。实测任务耗时与开始结束时间可见。
- 后端发出研究请求并等到有引用的回复，重复消息被去重，非法跨项目消息和循环等待被拒绝。
- 两个任务尝试写同一共享文件时，构建产物不覆盖对方，集成门可准确报告冲突。用户停止、模型 429、子任务超时、重启和重复运行均有明确状态。
- 测试失败时保留已有代码与证据，报告失败项和负责角色。验证通过后才交给主线验收。
- 旧候选及其他并行工作保持独立。交付本地 Git 增量、README、合成夹具、执行命令和证据，不要求生成安装包。
