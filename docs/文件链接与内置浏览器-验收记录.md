# 文件链接与内置浏览器（2026-11-14）

## 背景

用户（m04683）要求：Agent 输出里的文件路径（典型是刚生成的 `*.html`）像其他 agent 产品一样显示为可点击的蓝色链接，点击后用**内置浏览器**打开，并可切换为**外部浏览器**。参考形态见 Codex 桌面端右侧的浏览器分栏。

## 业界常见实现

| 项目 | 形态 | 打开方式 |
| --- | --- | --- |
| VS Code（Simple Browser 等内置预览） | Electron `webview` 分区 | webview 载入 URL，`openExternal` 交给系统浏览器 |
| Codex 桌面端 | 右侧浏览器 dock（Chromium 内核） | 内置页签，可导入 Chrome 数据 |
| open-webui / LobeChat | 纯 Markdown 渲染 | 链接新开标签页，无本地文件路径识别 |
| Cline / Roo Code / Continue | IDE 扩展 | 路径链接把 `openFile` 消息发给编辑器 host |
| Chatbox / Jan | Electron 客户端 | 链接统一 `shell.openExternal` |

结论：渲染层把「路径 / URL」转成链接，宿主负责「解析路径 + 提供 webview / 外部打开」是主流做法；桌面端想做到「点击就在应用内看页面」，Electron 里最直接的载体就是 `webview`（VS Code 同款思路）。本项目采用该路线。

## 实现

### 1. 文本识别（`src/renderer/src/RichText.tsx`）

- 正则同时匹配两类目标：
  - `https?://...`（URL）；
  - 带已知扩展名的路径：Windows `D:\...`、POSIX `/...`、相对路径 `a/b/c.html`，可带 `:行号`。
- 命中段落渲染成 `.inline-link` 按钮（文件蓝色、URL 绿色），其余文本原样保留，外层仍是 `white-space: pre-wrap`。
- 仅用于 assistant 正文；用户消息保持纯文本。

### 2. 路径解析（`src/main/ipc.ts`）

新增两个 IPC：

- `openfuture:link:resolve`：HTTP(S) 直接返回；否则去掉 `:行号`、按工作区解析相对路径、`statSync` 校验存在，返回 `{kind,url,path,isHtml}`（HTML/SVG 才算页面）。
- `openfuture:link:open-external`：URL 用 `shell.openExternal`，文件（含 `file://`）用 `shell.openPath`。

### 3. 内置浏览器（`src/renderer/src/BrowserPane.tsx`）

- 右侧 dock：前进/后退/刷新/地址栏、页面标题、「外部浏览器」、关闭。
- 主进程 `webPreferences.webviewTag: true`，并对 guest 做加固：
  - `will-attach-webview` 清空 preload、关闭 `nodeIntegration`；
  - `web-contents-created` 里把 `window.open` 交给系统浏览器，`will-navigate` 只允许 `http/https/file`。
- dock 打开时 `.main-panel` 让出 `clamp(360px, 40vw, 680px)`，对话不被遮挡。

### 4. 点击行为

- HTML/SVG 或 http(s)：在内置浏览器打开。
- 其它文件：交给系统默认程序（不抢 dock）。
- 解析失败（文件不存在等）：顶部错误条提示。

## 已知限制

- 只识别带已知扩展名的路径；无扩展名目录、裸文件名不会变蓝。
- 路径解析相对当前工作区；工作区外的绝对路径也可打开，但不会做二次确认。
- `<webview>` 不支持下载管理、开发者工具入口和前进缓存定制；后续可换 `WebContentsView` 获得更细的控制。
- 外部打开依赖系统默认程序；没有「选择用哪个浏览器」的配置。
