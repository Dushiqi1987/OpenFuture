# DSH 插件市场与自动适配（2026-11）

> 目标：把 DeepSeek Harness（DSH）的插件市场搬进 OpenFuture 左侧栏；用户点「下载」拿到的是 DSH 插件，
> 再由当前模型把它改写成 OpenFuture 的 Pi 扩展，点「适配」即可启用。

## 1. 结论先行

| 问题 | 结论 |
| --- | --- |
| DSH 插件能直接装进 OpenFuture 吗 | **不能**。DSH 插件是 cordis 插件（`export function apply(ctx, config)`，运行在 DSH 宿主的 cordis 容器里，依赖 `tools`/`settings`/`credentials`/`ui` 等服务），OpenFuture 的宿主是 Pi SDK 的 `ExtensionFactory`，两边 API 没有交集。 |
| 那市场还能接吗 | **能**。市场只负责「目录 + 下载 tgz」，与宿主无关；我们把目录读出来、下载解包，再让模型做一次「源码 → Pi 扩展」的改写即可。 |
| 改写质量靠什么保证 | 一份显式的**扩展契约**（`EXTENSION_CONTRACT`）+ 无工具只读会话 + 产物落成单文件 ESM；改写结果由用户显式启用，不自动生效。 |
| 现在做到哪一步 | 目录浏览、下载、卸载、模型适配、启用/停用、卸载适配产物全部打通；离线冒烟与桌面 E2E 均通过（见 §7）。 |

## 2. DSH 插件体系（调研结论）

DSH 的插件体系基于 [cordis](https://github.com/shigma/cordis)：

- 一个 **bundle** 就是一个 npm 包，`package.json` 里声明 `dsh.bundle.patch`（一段 YAML，安装时把插件行插进 DSH 配置）；
- 宿主插件入口导出 `apply(ctx, config)`（或一个 service 类），`inject = ['tools']` 之类声明依赖的服务；
- 元数据放在 `locale/zh.json`、`locale/en.json` 的 `meta.title` / `meta.description`，图标是 `./icon`；
- 安装由 DSH 的 `plugin_manager` 工具完成（`install_bundle`，从 npm registry 拉取）；
- 插件能读写配置（`ctx.get('configEditor')`）、拿机密（`ctx.credentials`）、注册工具与 UI 面板。

也就是说：**DSH 插件的价值在 cordis 容器提供的服务，而这些服务 OpenFuture 没有**，所以「装上来就能跑」是不成立的；必须做一次语义映射。

## 3. DSH 插件市场的数据源

市场本体是 [dsh-market/dsh-market](https://github.com/dsh-market/dsh-market)（MIT），发布物为 `dshmarket-<version>.tgz`，也是一个 DSH 插件。

它自己不维护目录，而是读官方目录 JSON：

- `CATALOG_OFFICIAL = 'https://awesome-dsh-plugin.com/plugins.json'`
- 中国网络回退：npm 包 `dsh-plugin-catalog`（镜像会改写 tarball 地址）
- 目录条目（`RegistryPlugin`）关键字段：`name`、`owner`、`url`、`category`（字符串或数组）、`description`（多语言）、`npm`、`tarball`、`stars`、`downloads`、`version`、`icon`、`install`、`releaseManifest`、`deprecated/replacement`、能力披露字段。

官方目录目前约 **14.6 MB** JSON。本机实测多次在 ~7.7 MB 处被网络中断（`Unterminated string in JSON`），因此：

- 应用到磁盘缓存（`plugins/catalog.json`，TTL 6 小时）；
- 支持 `OPENFUTURE_MARKET_CATALOG` 指向本地 / 镜像目录；
- 测试一律使用本地 fixture，不依赖外网。

**应用侧加载策略（2026-11-13 调整）**：默认优先 npm 镜像包 `dsh-plugin-catalog`（tgz 4.8 MB，本机 16.5 s；解包后与官方 JSON 同源、约晚一天），失败再回退官方 JSON；面板**有缓存立即打开**，过期后后台静默刷新——直接 `await` 官方 15 MB JSON 会把面板卡住数分钟（实测 12:43 点击、12:47 才写入缓存）。

## 4. OpenFuture 侧链路

```
左侧栏「插件市场」
  ├─ 目录  → PluginMarket.state()  →  GET catalog → 归一化成 MarketEntry[]
  ├─ 下载  → install(id)           →  tarball / npm url → gunzip + untar → <userData>/plugins/<id>/
  ├─ 适配  → adaptPlugin(id)       →  readSources(id) → 模型改写 → adapted/<id>/plugin.js + manifest.json
  └─ 启用  → host restart          →  openSession({ pluginExtensions }) → 动态 import(plugin.js) → factory(api)
```

关键文件：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 协议 | `src/shared/protocol.ts` | `MarketEntry`、`PluginMarketState`、`PluginAdaptProgress`、`AdaptedPluginInfo`、六个 API 与 IPC 通道 |
| 市场 | `src/main/plugin-market.ts` | 目录缓存、下载解包、源码读取、适配产物读写、启用清单 |
| 适配会话 | `src/agent-host/plugin-adapt.ts` | 无工具只读会话 + 扩展契约 + 代码块抽取 |
| 宿主 | `src/agent-host/index.ts` | `extensionFactories` 注入 `plugin:<file>`、`adaptPlugin` RPC |
| 主进程 | `src/main/ipc.ts` | 六个 handler、适配进度广播、适配后重启 Agent |
| 渲染 | `src/renderer/src/PluginMarketPanel.tsx` | 目录/已下载/已适配三段式面板 |

## 5. 适配契约（写进模型 prompt 的部分）

产物必须是**单个 ESM 文件**，默认导出工厂函数：

```js
export default function (api) {
  api.on('before_agent_start', async (event) => ({ systemPrompt: `${event.systemPrompt}\n\n<plugin>…</plugin>` }))
  api.registerCommand('demo', { description: '…', handler: async (args) => ({ text: '…' }) })
  api.registerTool({
    name: 'dsh_demo',
    label: 'Demo',
    description: '…',
    parameters: { type: 'object', properties: {} },
    execute: async () => ({ content: [{ type: 'text', text: '…' }] })
  })
}
```

约束：

- 除「5.1 npm 依赖」里声明的包外，禁止 `import` / `require`、网络请求、写盘、执行 shell；
- 可用事件：`before_agent_start`、`agent_end`、`tool_call`、`tool_result`；
- 可用注册：`registerCommand`、`registerTool`（工具名统一 `dsh_` 前缀）；
- 原本依赖 UI 面板的插件，降级成「命令 + 提示注入」，并在 `note` 里说明丢失的交互；
- 模型先给 3–6 行说明，再只给一个 ```js 代码块（`fenceCode()` 取最后一个块）。

### 5.1 npm 依赖（P1，2026-11-13）

模型可以请求第三方 npm 包，但必须显式声明，用户点按钮才会安装：

```js
// deps: ssh2@^1.15.0
import ssh2 from 'ssh2'
```

- 契约允许「最多 6 个公开 npm 包」，仍然禁止 `node:*` 内置模块、`child_process`、写盘与自建监听；
- 宿主从代码里解析依赖：`// deps:` 头优先，裸 `import` 兜底（`declaredRequires()`），写进 `manifest.json` 的 `requires`；
- 安装器是自实现的（`src/main/plugin-deps.ts`，不依赖系统 npm）：查 registry（`OPENFUTURE_NPM_REGISTRY` 可指向镜像）→ 自写 semver 子集选版本 → 下载 tgz → 解包并**扁平安装**到 `<userData>/plugins/adapted/<id>/node_modules` → 写 `openfuture-deps.json`；
- 上限：80 个包 / 80 MB 总量 / 20 MB 单包；不执行 `postinstall` 等生命周期脚本，也不编译原生模块；
- 依赖未装齐时 `enabledPluginFiles()` 会跳过该插件（避免宿主里报模块找不到），面板显示「安装依赖（N）」；装完后自动重启 Agent 生效。

验证：

- `node tools/plugin-deps-smoke.mjs`：本地假 registry，断言版本选择、传递依赖、ESM 导入、未知包报错；
- `E2E_PLUGIN_DEPS=1 node tools/e2e-plugin-market.mjs`：适配产物带 `// deps: is-number@7` → 面板出现「安装依赖（1）」→ 点完重启后宿主日志出现 `[agent-host] adapted plugin loaded`。

实际案例：真实模型适配 `@linxin666/dsh-ssh` 时自动生成 `// deps: ssh2@^1.15.0`，安装器 3.3 s 装下 `ssh2` 及 4 个传递依赖，`plugin.js` 能正常 import 并导出工厂函数。


### 5.2 工具与命令如何进入会话（2026-11-13）

适配产物只有两类能力真正落地：`registerTool` 工具与 `registerCommand` 命令。

- **工具**：Pi 的 `createAgentSession({ tools })` 是会话级 allowlist，扩展运行时注册的工具同样要过 `_isAllowedTool` 过滤（`dist/core/sdk.js`、`dist/core/agent-session.js` 的 `_refreshToolRegistry`）。我们的 `tools` 在扩展加载前由 `customTools.map(name)` 定下，所以必须显式加入 `dsh_*` 通配，否则插件工具「加载成功但不在会话里」（日志 `extensionErrors=[]`，很难察觉）。
- **命令**：`session.prompt(text, { expandPromptTemplates: true })` 会先尝试扩展命令处理器（`_tryExecuteExtensionCommand`）；传 `false` 则把 `/ssh add` 当普通消息发给模型。`src/agent-host/index.ts` 的 `sendMessage` 只在输入匹配 `/^\s*\/[A-Za-z][\w-]*(\s|$)/` 时打开展开，项目本身 `noSkills/noPromptTemplates`，所以不会误展开别的资源。
- **可见性**：左侧栏「插件」面板顶部列出 `PluginMarketState.adapted`（启用/停用/移除、依赖状态）；启用状态写入 `manifest.json`，宿主每次开会话时通过 `pluginExtensions` 加载。

## 6. 安全边界

- 生成代码在 **agent-host 进程里执行**，没有沙箱；等价于用户主动安装了一个本地扩展，必须通过「适配」按钮显式触发；
- 适配产物默认启用，但可以在面板里一键关闭或删除；
- 契约禁止网络/写盘/执行命令，但这是**提示词约束，不是运行时沙箱**；后续可加静态检查（禁 `child_process`/`fetch`/`fs`）与 Node `vm`/worker 隔离；
- 下载的 tarball 有 40 MB 上限、路径穿越校验（拒绝 `..` 与绝对路径）、解包后必须是含 `package.json` 的包。

## 8. 踩过的坑（复用价值）

1. **tar 头偏移**：`extractTar` 最初用「归档偏移」去读文件名，从第二个条目起读到的是 size/mtime 字节 → 文件名变成乱码。修复：`tarName(header, 0)`，偏移只用于算数据区。
2. **适配产物路径重复**：`readAdapted()` 返回的 `file` 已是绝对路径，`enabledPluginFiles()` 又 `join(adaptedDir, file)`，宿主日志报 `adapted plugin missing: ...\adapted\x\D:\...\plugin.js`。修复：直接返回 `item.file`。
3. **适配 ID 解析**：preload 传的是字符串 `id`，IPC handler 只处理 `{ id }` 对象 → 报「缺少插件 ID」。修复：同时接受字符串与对象。
4. **mock 读不到 prompt**：Pi 发来的 `message.content` 是 parts 数组，直接 `message.content` 当字符串会得到空 → 必须用 `textOf()` 拼接。
5. **目录断流**：14.6 MB 目录在本机 ~7.7 MB 处被掐断，`JSON.parse` 报 `Unterminated string`；测试改用本地 fixture，应用侧保留磁盘缓存与可配置目录地址。
6. **点「插件市场」弹出「关于 OpenFuture」**：`App.tsx` 里通用面板弹窗对 `dshPanel` 只识别 `agents/plugins/automation/computer/more`，新增的 `plugin-market`、`group-chats` 落到 else 分支，标题变成「关于 OpenFuture」，并且这个空弹窗盖在真正的面板上。修复：通用弹窗条件改成 `dshPanel && dshPanel !== 'plugin-market' && dshPanel !== 'group-chats'`，并把 E2E 的点击改成真实鼠标事件 + 断言页面上没有多余的 `.dsh-modal`。
7. **限高 flex 列里的「已下载」行溢出**：`.plugin-market-modal` 是 `max-height` + `flex-direction: column`，`.plugin-section` 默认 `flex: 0 1 auto` 会被压缩到内容高度以下，行没有 `overflow` 裁剪 → 「适配」按钮被下面的「目录」工具栏盖住。修复：`.plugin-section { flex: 0 0 auto }`、列表包 `.plugin-list-compact { max-height: 26vh }` 独立滚动、行与按钮 `flex: 0 0 auto`，工具栏 `flex-wrap: wrap`。教训：**任何 `max-height` 的 flex 列，子段都要显式 `flex: 0 0 auto` 或自带滚动**，否则内容会静默溢出并叠到后续兄弟节点上。
8. **适配会话 401**：`pluginAdapt` handler 直接调宿主，没像 `sessionSend` / `groupChatStart` 那样先推凭据；host 启动后没发过普通消息时，适配会话用占位 key → 401 → 空 assistant → 报「模型没有返回可解析的 JavaScript 代码块」。修复：适配前 `host.setCredential(active.providerId, active.apiKey)`；`plugin-adapt.ts` 遇到 `stopReason === 'error'` 直接抛「模型调用失败：<errorMessage>」，不要再伪装成格式错误。教训：**每新增一个「可能先于普通对话发生的模型入口」，都要检查它是否推过凭据**（群聊、适配、以后可能的摘要/标题生成）。
9. **目录下载阻塞面板**：`pluginMarket` handler 在无缓存时同步 `await` 官方 14.9 MB JSON，本机链路断流，面板 4 分钟停在「载入中」，用户报「插件商店打不开了」。修复：默认走 npm 包 + 失败回退官方、有缓存立即返回、首次加载显示 20 秒提示。教训：**永远不要在打开面板的 IPC 路径里同步等一个 10 MB 级网络资源**——先返回缓存/已装数据，再后台刷新。
10. **适配产物注册的工具被 allowlist 静默丢弃**：`createAgentSession({ tools })` 的 `tools` 是会话允许的工具名列表，扩展在运行时 `registerTool` 注册的工具也要过这套过滤（见 Pi `sdk.js` 的 `_isAllowedTool` / `agent-session.js` 的 `_refreshToolRegistry`）。我们的 `tools = customTools.map(name)` 在扩展加载前就已定下，于是插件注册的 `dsh_*` 工具全部被过滤、日志只显示 `extensionErrors=[]`，很难看出问题。修复：有适配插件时显式 `tools.push('dsh_*')`（allowlist 支持通配），并把 `dsh_` 从子 Agent / 群聊角色的工具集里排除。教训：**运行时注册的工具必须被会话 allowlist 覆盖，否则它"加载成功但不可见"**。
11. **依赖安装的三个坑**：① MSYS bash 里 `npm.cmd` 退出码 126，不能再 shell 出去调 npm，必须自己做 registry 安装器；② npm 的 `7` / `7.0` 是范围（`>=7.0.0 <8.0.0`）而不是精确版本，semver 子集漏了这条会报「找不到满足 is-number@7 的版本」；③ `ssh2@1.17.0` 的 tarball 根目录是 `mscdex-ssh2-5c506eb/` 而不是 `package/`，解包后要 `flattenPackageDirectory()` 上移，否则 Node 解析到 `node_modules/ssh2/index.js` 时找不到文件。教训：**外部数据（依赖元数据、tar 结构）永远不能信**，要有兜底和可读错误。

## 9. 已知限制与后续

| 限制 | 影响 | 后续 |
| --- | --- | --- |
| 官方目录 14.6 MB、易断流 | 真实网络下「刷新目录」可能失败 | 已支持本地 JSON 目录与「刷新失败仍显示已下载」；断点续传 / npm `dsh-plugin-catalog` 镜像回退仍待做 |
| 无运行时沙箱 | 生成代码拥有宿主权限 | 静态检查 + worker/vm 隔离 + 权限清单 |
| 契约表达能力有限 | 依赖 cordis 服务/UI 的插件只能降级 | 扩充 `api` 表面（如 registerPanel 占位） |
| 无版本升级流程 | 已下载插件不会自动跟进新版本 | 目录版本对比 + 「更新」按钮 |
| 依赖只做扁平安装 | 需要多版本共存的插件会解析到同一份副本 | 嵌套 node_modules / 冲突时提示用户 |
| 不跑生命周期脚本、不编译原生模块 | 需要 `node-gyp` 的包装不上 | 检测到 `install` 脚本时提示「请手工安装」|
| 适配质量依赖模型 | 复杂插件可能只改出空壳 | 适配后用「加载 + 冒烟调用」自动验收，失败要模型重试一轮 |

## 10. 复现

```bash
# 1) 离线冒烟（不依赖外网）
node tools/plugin-market-smoke.mjs

# 2) 桌面 E2E（本地 fixture + mock 模型 + Electron）
node tools/e2e-plugin-market.mjs

# 3) 依赖安装 + 适配后加载
E2E_PLUGIN_DEPS=1 node tools/e2e-plugin-market.mjs

# 4) 指向自定义目录（本地文件或镜像）
OPENFUTURE_MARKET_CATALOG=/path/to/plugins.json pnpm dev
```

环境变量：

- `OPENFUTURE_MARKET_CATALOG`：目录地址（默认 `https://awesome-dsh-plugin.com/plugins.json`）；
- `OPENFUTURE_NPM_REGISTRY`：依赖安装用的 npm registry（默认 `https://registry.npmjs.org`，可指向镜像）；
- `MOCK_PLUGIN_ADAPT=1`：mock 模型进入插件适配模式（仅测试用）；
- `MOCK_PLUGIN_DEPS=1`：适配产物带 `// deps:` 头，便于验证「安装依赖」按钮（仅测试用）。
