# 中途引导与排队验收记录

## 目标

运行中的对话允许继续输入，并区分两种投递语义：

- **引导（steer）**：等当前工具调用完成、下一次模型请求前投递。
- **排队（queue）**：等当前 assistant 轮次完全结束后投递。

使用 Pi AgentSession 原生 `steer()` / `followUp()`，不复制 Codex 的队列实现。

## 实现

- 协议 `SendMessageMode = 'prompt' | 'steer' | 'followUp'`；`sendMessage(text, mode)`。
- `AgentStreamEvent` 增加 `user-message`，用于把乐观 pending 消息转为已投递。
- agent-host：
  - 运行中 `steer` → `session.steer(text)`；其他 → `session.followUp(text)`。
  - 不再返回 `BUSY`。
  - `message_start` 的 user 消息转发给 renderer。
- Composer：
  - 运行中 Enter 排队，Ctrl/Cmd+Enter 引导；右侧出现“排队 / 引导 / 停止”。
  - 待投递消息显示“引导中 · 当前工具结束后发送”或“已排队 · 本轮结束后发送”。
  - 停止时取消未投递消息，清掉 pending 标签，并把最后一条未发送内容放回输入框。
- 停止后 Pi 不保留可投递的 follow-up；UI 同步取消。

### 后端引导

- session `01a1c5cf-2b71-76ed-b738-d8d8ec3edae5`
- 60 秒 PowerShell 工具执行中投递引导。

- 未出现 `PHASE1_DONE`，说明引导在工具结果后、下一次模型调用前投递。

- 证据：`.scratch/stop-ui-result.json`、`.scratch/stop-queue-result.json`

## 限制

- 仅支持文本；图片/文件消息未纳入排队。
- pending 是 renderer 乐观状态；会话 JSONL 只记录真正投递的消息。
- 正常发送按文本 15 秒内匹配乐观消息，极快重复同文本可能误合并。
- 未重打 EXE。
