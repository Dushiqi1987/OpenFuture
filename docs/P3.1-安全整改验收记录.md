## 2. 撤销笔记不再注入

### 实现

- `src/memory-host/index.ts`：新增 `workspace_revision`、`L3Entry`、`L3Context`；`knowledge_versions` 增加 `projection_json` 与 `workspace_revision`。
- `l3ContextFor(workspaceId, mode)` 每次调用按当前数据库重新校验条目：
  - note 必须 `status='active'` 且条目 revision 与笔记 revision 相等；
  - source 必须 active、revision 相等且有 active evidence；
  - 不满足条件的条目在构建上下文前剔除。
- 旧版本没有 `projection_json` 且存在旧 `l3_content` 时返回 `needsReview:true`、不注入文本；普通对话仍可用。
- `src/agent-host/index.ts`：通过 Pi 扩展 `before_agent_start` 每轮向主进程请求 `L3Context`，替换系统提示中的 `<memory_context>`；不再在会话打开时固定 L3 文本。
- `src/main/agent-host.ts` / `src/main/index.ts`：增加 `context-request` / `context-response` 桥；`sessionOpen` 不再读取 `dreamState.active.l3Content`。

## 3. grep 恶意正则不再阻塞停止

### 实现

- `src/agent-host/workspace-tools.ts`：正则 grep 移入 `worker_threads` Worker（`GREP_WORKER_SOURCE`，`eval:true`），超时 `GREP_WORKER_TIMEOUT_MS=1500`。
- Worker 内编译正则、读取文件（≤4MB、NUL 跳过）、按行匹配并返回结果；顶层主体包进 IIFE，避免 eval Worker 的 `Illegal return statement`。
- 超时、AbortSignal、Worker error/exit 都会 `worker.terminate()` 并只 settle 一次；超时返回“grep 正则匹配超时（1500ms）…”，取消返回“grep 已取消”。
- 文件收集仍由主进程的 `WorkspacePolicy` 完成，保留工作区边界、junction/敏感路径/大小/输出限制。

### 实测

测试输入 `grep:(a+)+$|regex-line.txt`（`regex-line.txt` 为 40 个 `a` 加 `!`）：

| 环境 | 停止耗时 | 结果 |
| --- | --- | --- |
| 开发版 CDP 9235 | 52 ms | 状态“生成中”→“就绪”，无错误 banner，toolResult 为“grep 已取消” |
| 打包版 CDP 9236 | 53 ms | 同上 |
| 同会话继续发问 | 成功 | 停止后同一会话继续得到回复 |
| 正常正则 `grep:a+|regex-line.txt` | 成功 | 返回 `regex-line.txt:1: aaaa…!` |
| A1 越界 `read:../p01-outside/secret.txt` | 拒绝 | `[安全策略] 拒绝访问：路径越界…secret.txt` |
