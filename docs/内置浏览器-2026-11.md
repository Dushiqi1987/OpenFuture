# 内置浏览器：与 Agent 共用同一个页面

> 目标：把「只读预览窗」升级成 Codex 式可操作浏览器——用户在右侧 dock 里正常浏览，Agent 能打开网页、读正文、点击、输入、按键、滚动，并在需要时截图存盘。

## 1. 与 Codex 的对齐点

| 能力 | Codex | OpenFuture |
| --- | --- | --- |
| 用户可见的浏览器面板 | 有 | 右侧 dock（地址栏、缩放 80%–150%、加载进度、标题） |
| Agent 打开网页 | `open` | `browser_open`（非 URL 自动走 Bing 搜索） |
| 读页面正文 | `read` | `browser_read`（`innerText`，可截断） |
| 点击 / 输入 / 按键 | 有 | `browser_click`（selector 或可见文本）、`browser_type`（可回车提交）、`browser_press` |
| 滚动 / 前进后退 / 刷新 | 有 | `browser_scroll`、`browser_back`、`browser_forward`、`browser_reload` |
| 截图 | 有 | `browser_screenshot`（主进程 `capturePage`，存到工作区） |
| 与用户共用状态 | 有 | 是——Agent 操作的页面就是用户眼前那个 webview |

## 2. 架构

```
agent-host (Pi 工具循环)
  browser_* 工具 ──requestHostTool──▶ main: handleBrowserToolForWorkspace
                                        │
                                        ▼
                              BrowserBridge.command()
                                        │ IPC: openfuture:browser:command
                                        ▼
                            renderer: BrowserPane.runCommand()
                                        │ <webview> 执行 DOM/导航
                                        ▼
                        IPC: openfuture:browser:reply ──▶ BrowserBridge.settle()
                                        │
                                        ▼
                       screenshot 分支：main.webContents.fromId(id).capturePage()
```

- **为什么截图不在渲染层做**：`<webview>.capturePage()` 在本机实测先抛 `UnknownVizError`，随后整个 Promise 挂起，只能等 25s 超时。改为渲染层只回 `captureId = webview.getWebContentsId()`，由主进程 `webContents.fromId(id).capturePage()` 捕获，失败重试 4 次（间隔 400ms），稳定成功。
- **为什么工具在 agent-host、执行在渲染层**：页面状态属于 UI，只有渲染层能可靠地等待 `dom-ready` / `did-stop-loading`；主进程负责 IPC 转发与超时，工具层只描述「想做什么」。

## 3. 工具表

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `browser_open` | `url` | 打开地址；非 URL 走 Bing 搜索；等待加载完成（35s 超时） |
| `browser_read` | `maxChars?` | 返回 `document.body.innerText`，默认 8,000 字符 |
| `browser_screenshot` | — | 截图存 `<workspace>/.openfuture/browser/browser-<ISO>.png`，返回路径 |
| `browser_click` | `selector?` / `text?` | CSS 选择器，或按可见文本匹配 `a/button/input/li…` 并点击 |
| `browser_type` | `text` / `selector?` / `submit?` | 原生 setter 写值 + `input/change`；`submit` 派发 Enter 并 `form.requestSubmit()` |
| `browser_press` | `key` | 键盘事件（Enter/Tab/Escape/Arrow…） |
| `browser_scroll` | `deltaY` | 滚动页面 |
| `browser_back` / `browser_forward` / `browser_reload` | — | 导航 |

所有工具都带 25–40s 超时；超时返回 `BROWSER_TIMEOUT`，不会把 Agent 卡死。

## 4. 安全边界

- `<webview>` 清空 `preload`、`nodeIntegration=false`、`contextIsolation` 保持开启；导航只允许 http(s)/file，`window.open` 交给系统浏览器。
- 子 Agent 的工具过滤排除所有 `browser_*`，避免并行子任务争抢同一个页面。
- 截图落盘限制在工作区 `.openfuture/browser/` 下，文件名带 ISO 时间戳，不覆盖历史截图。

## 5. 已知限制

- 单标签页：一个 dock 对应一个页面；多标签后续可做。
- 不穿透 iframe 与 shadow DOM 的深度内容（`innerText` 只取顶层文档）。
- `browser_type` 默认找第一个可见 `input/textarea`；复杂表单用 `selector`。
- 截图是 webview 视口（可见区域），不是整页长图。
