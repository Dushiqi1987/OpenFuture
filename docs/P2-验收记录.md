## 2. 实现

### 2.1 协议与存储

- `src/shared/protocol.ts`：`DreamPhase`、`DreamOpType`、`DreamOp`、`DreamJob`、`DreamVersion`、`DreamState`、`DreamApplyInput`、`DreamRollbackInput`、`DreamRevokeInput`；7 个 dream API/通道。
- `src/memory-host/index.ts` 新增：
  - `dream_jobs(id, workspace_id, status, phase, ops_json, l3_preview, delete_ratio, publish_id, error, created_at, updated_at)`
  - `knowledge_versions(id, workspace_id, publish_id UNIQUE, label, l3_content, ops_json, summary, status, created_at)`
  - `workspace_knowledge(workspace_id PK, active_version_id, previous_version_id, updated_at)`

### 2.2 裁决与发布

- 确定性 planner：超过 30 天未更新的笔记 → `demote`；同标题笔记 → `merge`；没有同名笔记的来源 → `promote`；其余 active 项 `keep`。
- 每个 op 带 `opId / targetIds / evidenceRefs / reason / confidence / expectedRevision`；删除比例上限 25%。
- L3 预算：200 行 / 25,000 UTF-8 字节 / 1,500 token（按字节 / 4 近似），先到者截断。
- `dreamApply`：`publishId` 幂等；只接受 `review`；事务内应用 ops、创建版本、旧版本置 `superseded`、更新 active；事务外写 `memory/injected/MEMORY.md`，写前把旧文件镜像到 `memory/mirrors/<versionId>.md`。
- `dreamRollback` 回到上一版或指定版；`dreamRevoke` 标记撤销并按回退版本重写 L3。

### 2.3 L3 注入

- `src/main/ipc.ts` 的 `sessionOpen` 读取 `dreamState.active.l3Content`，传给 `AgentHost.open(..., l3Content)`。
- `src/agent-host/index.ts` 的 `DefaultResourceLoader.systemPromptOverride` 把 L3 追加到系统提示：
  `<memory_context> ... </memory_context>`。
- 修复点：`dispatch` 的 `open` 分支此前漏传 `l3Content`，已补；日志保留 `[agent-host] open session mode=... l3Bytes=...`。

### 2.4 UI

- 记忆库面板总览底部新增 Dreaming 区：开始 Dreaming、待审 ops 列表、L3 预览、发布/拒绝、版本列表、回滚上一版/指定版、撤销。
- 发布时使用 `publish-${Date.now()}-...` 作为幂等键。

## 4. 偏离与限制

1. planner 是确定性规则，不调用模型；没有真实 LLM 裁决。
2. `phase` 固定为 `promote`，未持久化 Ingest→Light→REM→Deep 的阶段进度。
3. P2 的 merge 只更新第一个目标，未撤销其余重复笔记；P3 已修复该行为。
4. 撤销 active 版本时写入空 MEMORY.md，而不是删除文件。
5. 引用仅实时显示；会话重开不恢复 citations。
6. 打包未签名、默认图标、`asar:false`；本轮无安装包。
7. P2 不含质量门、预算与空闲调度；这些在 P3 补齐，见 `docs/P3-验收记录.md`。
