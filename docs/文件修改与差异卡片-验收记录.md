# 文件修改与差异卡片 · 验收记录

- 日期：2026-11-15
- 范围：`write` / `edit` 工具、工作区写策略、逐文件增删统计、Codex 风格「已编辑 N 个文件」卡片、设置开关
- 环境：Windows 11 x64，Node 24.21，Electron 45.2.3，Pi SDK 1.5.0，mock 模型（`MOCK_WRITE=1`）

## 1. 目标

模型改完文件后，对话里要像 Codex 一样出现一张汇总卡片：

```
已编辑 2 个文件                         +439 −421
────────────────────────────────────────────
LICENSE                                  +21  −0
README.md                               +418 −421
```

点击某一行应能打开对应文件，卡片在流式过程中实时累加。

## 2. 实现

| 层 | 位置 | 内容 |
| --- | --- | --- |
| 协议 | `src/shared/protocol.ts` | `FileChange { path, added, removed, kind }`；`AgentStreamEvent` 新增 `{ type: 'file-change', change }`；`PublicSettings.allowFileWrites`、`SetToolAccessInput.allowFileWrites` |
| 工具 | `src/agent-host/workspace-tools.ts` | 新增 `write` / `edit` 工具；`trackFileChanges()` 在执行前后读取快照，按行统计增删；子 Agent 过滤器排除 `write`/`edit`，避免并发覆盖 |
| 写策略 | `src/agent-host/workspace-policy.ts` | `assertWritableFile` / `assertWritableDirectory`：目标必须在工作区内、父目录可写、不触碰受保护目录（应用配置、会话、密钥）与敏感文件名 |
| 宿主 | `src/agent-host/index.ts` | `createWorkspaceToolset(..., { allowWrites, onFileChange })`；`onFileChange` → `sendEvent({ type: 'file-change', change })` |
| 设置 | `src/main/settings-store.ts` / `src/main/ipc.ts` / `src/renderer/src/SettingsDialog.tsx` | `allowFileWrites` 默认开启；经 `OPENFUTURE_ALLOW_FILE_WRITES` 传给 agent-host；「工具与权限」新增「允许 Agent 修改文件（write / edit）」 |
| 渲染 | `src/renderer/src/App.tsx` / `styles.css` | `UiMessage.changes` 累积；`buildAssistantTurn` 按路径合并；`AssistantTurnView` 渲染 `.file-changes` 卡片，点击行调用 `onOpenPath` 打开文件 |

### 差异统计

- 先裁掉公共前后缀，再对中间段做 LCS（`Uint32Array` 双行滚动）；两段行数乘积超过 400 万时退化为「整段全部新增/删除」，避免大文件卡顿。
- 单文件快照上限 2 MB；`create` / `delete` 直接按行数计。

## 4. 已知限制

- 卡片只活在当前回合：重新打开对话后回放回答与工具名，不重新计算增删行数。
- 只有 `write` / `edit` 会产生 `file-change`；PowerShell 里执行的写操作不会进入卡片。
- 没有逐次写审批，写权限只有一个全局开关；每次写仍受工作区策略约束。
