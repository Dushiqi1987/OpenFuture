# 时间注入与前缀缓存验收记录

## 背景

用户在“医疗专家智能体”会话中看到会话状态栏显示“缓存命中 0.0%”，6 轮对话、83.8K token 均未命中 provider 前缀缓存。

## 根因

上一版为了修正普通对话的日期错误，在每轮 `before_agent_start` 中把包含 `HH:mm` 的 `<current_time>` 注入 system prompt 最前面。system prompt 每分钟变化，导致 provider 看到的第一 token 就不同，工具定义和全部历史无法复用前缀，`cacheRead` 始终为 0。

Agent 角色提示是静态的，不是原因；所有会话都会受影响。

## 修复

- system prompt 只注入当天日期（`YYYY/MM/DD 星期X`，Asia/Shanghai），同一天内保持不变。
- 新增 `current_time` 工具；需要精确到分钟的时间时由模型调用，返回完整日期时间。
- system prompt 中明确提示“需要精确到分钟时调用 current_time 工具”，并保留“不要凭训练数据猜测日期”的约束。
- `current_time` 加入每次会话的工具列表，因此工具定义也保持稳定。

## 验证

正式 Qwen3.7 Flash、记忆关闭、全新会话：

1. 第一问：“今天是几号？星期几？请直接回答，不要调用任何工具。”
   - 回答：“今天是 2026 年 11 月 11 日，星期三。”
   - 首次请求 `input=12722`、`cacheRead=0`（首次请求冷启动，属正常）。
2. 第二问：“现在几点？请调用 current_time 工具后回答。”
   - 模型调用 `current_time`；
   - 工具调用后的 assistant `input=372`、`cacheRead=12416`；
   - 最终回答：“现在是 2026 年 11 月 11 日星期三 19:09:58（Asia/Shanghai）。”
   - 最终 assistant `input=471`、`output=56`、`cacheRead=12416`、`totalTokens=12943`；
   - prompt token = `471 + 12416 = 12887`，缓存命中率 = `12416 / 12887 ≈ 96.35%`。

会话：`01a1ca4c-d0b0-716f-b7a2-73128da56055`
证据：`.scratch/time-cache-result.json`

## 预期

- 首次请求 `cacheRead=0` 是正常的；从第二轮开始应命中。
- 同一天内连续对话，system prompt 前缀稳定，缓存命中率应明显回升。
- 跨天或跨会话首次使用仍可能冷启动。
- 精确时间只在模型主动调用 `current_time` 时产生新的尾部工具消息，不破坏之前已缓存的前缀。

## 构建

- `out/main/agent-host.js`（包含 `current_time` 工具与 date-only system prompt）
- 前端沿用 `index-CGIK5_Cv.js` 766.77 kB、CSS 78.79 kB。

## 限制

- `current_time` 依赖模型主动调用；若用户只问日期，system prompt 的日期块已足够。
- 该修复针对 OpenAI 兼容前缀缓存；不保证所有 provider 都提供相同缓存计量。
- 会话状态栏的“缓存命中”来自最近一次 usage；首次请求会显示 0%，第二轮后恢复正常。
