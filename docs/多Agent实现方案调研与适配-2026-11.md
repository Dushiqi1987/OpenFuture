# 多 Agent 实现方案调研与项目适配

> 日期：2026-11-11
> 范围：Desktop Agent 的多 Agent / 子 Agent 协作方案调研；OpenFuture（Electron + Pi SDK 1.5.0）落地实现与验证。
> 相关文档：`docs/OpenFuture-多Agent协作设计-v0.4.md`（原 HTTP 桥 + 任务图原型）、`docs/多Agent会话-验收记录.md`（角色会话 v0.4）、`docs/测试-隔离环境与Mock.md`。

## 1. 结论（TL;DR）

1. 生态里的「多 Agent」可以归为四类实现形态：**进程内会话委派**、**独立进程/沙箱 worker**、**外部编排框架**、**跨厂商协议互通**。它们解决的问题不同，不是同一条技术路线的四个版本。
2. 对本项目最合适的是第一类：**在 agent-host 进程内创建多个真实 Pi 会话**。理由：
   - Pi SDK 的 `createAgentSession` + `SessionManager.create(..., { parentSession })` 已经原生支持多会话并行、独立上下文、父子会话树与独立取消；不需要新进程、新端口、新协议。
   - 现有 agent-host 已把模型、工具、事件管线都准备好了；子会话复用同一 `ModelRuntime`、`SettingsManager` 与工作区工具，边际成本只有一次会话初始化。
   - 外部编排框架（LangGraph/crewAI/AutoGen 等）要么是 Python 生态，要么要求把 Agent 循环搬进它们的运行时，与 Pi 的 turn/tool 事件模型冲突，迁移成本远大于收益。
3. 已落地 P0：`delegate_tasks` 工具 + `SubagentRuntime`。主 Agent 一次派发 1–4 个自包含子任务，最多 3 个并行执行，结果汇总成文本回到父会话；子会话文件挂在父会话下，支持超时、取消与逐任务进度事件。
4. **可直接复用的开源代码**：
   - `pi-subagents`（MIT）：子会话构建方式（`createAgentSession` + `SessionManager.create(..., { parentSession })` + `bindExtensions({ mode: 'print' })`）、结果取最后一条 assistant 文本、输出上限与日志落盘策略，本实现与其同构。
   - Pi SDK 官方示例 `examples/extensions/subagent/index.ts`：single / parallel / chain 三种模式语义、并发上限、结果截断，可直接照搬工具契约。
   - `openai/openai-agents-js`（MIT）：handoff 与 agents-as-tools 的接口形状，适合作为后续「角色/交接」能力的参考，不建议直接引入。
   - `parallel/multiagent`（本仓库原型，M0 任务图 + 角色卡 + 收件箱）：保留为上层**规划器**，本实现作为其**执行器**的线上化版本。
5. 不建议引入任何重型框架。调研的 20 余个项目中，没有一个能在「Electron 内嵌 Pi + 单用户桌面 + 本地优先」约束下显著降低改造成本。

## 2. 四种实现形态对比

| 形态 | 代表实现 | 优点 | 代价 | 与本项目适配 |
| --- | --- | --- | --- | --- |
| 进程内会话委派 | pi-subagents、Pi 官方 subagent 示例、Claude Code Task、本实现 | 零 IPC 开销；共享模型/工具/事件；父子会话可追溯；取消语义清晰 | 共享进程内存与工作区；需要自己做并发、预算、结果聚合 | **采用** |
| 独立进程 / 沙箱 worker | Claude Code worktree agent、Cline 子任务、Codex cloud | 隔离强；可指定不同 cwd/worktree；崩溃不互相影响 | 每次启动新运行时；工具/凭证/事件都要重新接；Windows 上进程管理复杂 | 作为 P1 的「写任务隔离」选项 |
| 外部编排框架 | LangGraph、crewAI、AutoGen、microsoft/agent-framework、mastra | 图/状态机/检查点/人在环成熟；可观测性好 | 需要把 Agent 循环交给框架；与 Pi 的 turn 生命周期、工具审批模型冲突；多为 Python | 不采用（语义可借鉴） |
| 跨厂商协议 | A2A、MCP、OpenAI Agents handoff | 跨运行时互操作；生态兼容 | 需要服务端与网络暴露；桌面单机收益低 | P2 预留（远程 worker / 工具暴露） |

## 4. Pi SDK 提供的原语与缺口

已具备（1.5.0，`node_modules/@earendil-works/pi-coding-agent`）：

- `createAgentSession(options)` → `{ session, extensionsResult, modelFallbackMessage }`；`options` 支持 `cwd`、`agentDir`、`modelRuntime`、`model`、`thinkingLevel`、`tools`（名称白名单）、`customTools`、`sessionManager`、`settingsManager`、`resourceLoader`。
- `SessionManager.create(cwd, sessionDir?, { parentSession })`：子会话以父会话文件为 `parentSession`，写入 `session` 头，形成可追溯的会话树；`SessionManager.open/findById/list` 支持回读。
- `AgentSession`：`subscribe(cb)`、`prompt(text)`、`steer`、`followUp`、`abort()`、`dispose()`、`messages`、`isStreaming`、`sessionFile`、`sessionId`。
- 每会话独立上下文窗口、独立事件流；`ExtensionFactory` 可注入 system prompt 扩展。

缺口（必须自己实现）：

- 没有编排层：任务拆分、并发上限、结果聚合、预算与超时都没有。
- 没有「子 Agent 结果」的结构化回传；父会话只能拿到工具返回文本。
- 没有跨会话的工作区写锁；同一工作区的并行写需要上层约束。
- 没有子会话事件的 UI 归因；事件都带父 `sessionId`，需要额外 `taskId` 区分。

## 5. 本项目改造分析

改造前的 agent-host 是**单会话**结构（`src/agent-host/index.ts`）：

- 模块级 `current: AgentSession | null`、`busy`、`abortRequested`、`currentAssistantId`；
- `openSession` 先 `disposeCurrent()`；`sendMessage` 用全局 `busy` 串行化；`stop()` 只停当前会话。

关键判断：**不需要把整个 host 改成会话表**。子会话只在一次 `delegate_tasks` 调用期间存在，生命周期由 `SubagentRuntime` 管理；父会话仍是唯一「前台会话」，`busy`/`stop`/`settled` 语义不变。这样改动面最小，也避免重写 951 行的 session 管理。

需要新增的只有三处：

1. 子会话工厂与调度器（新文件）；
2. `delegate_tasks` 工具（新文件）；
3. `openSession` 接线 + `stop()`/`disposeCurrent()` 取消子会话 + 协议事件 + 渲染层进度条。

## 6. 本次实现

### 6.1 文件清单

| 文件 | 作用 |
| --- | --- |
| `src/agent-host/subagent-runtime.ts` | `SubagentRuntime`：子会话工厂、并发队列、超时/取消、结果聚合 |
| `src/agent-host/subagent-tools.ts` | `delegate_tasks` 工具定义、参数校验、结果格式化 |
| `src/agent-host/index.ts` | `openSession` 构造运行时并注册工具；`stop`/`disposeCurrent` 级联取消 |
| `src/shared/protocol.ts` | `SubagentTaskState` + `AgentStreamEvent` 新增 `subagent` 事件 |
| `src/renderer/src/App.tsx` | 子 Agent 进度条状态与渲染 |
| `src/renderer/src/styles.css` | `.subagent-strip` 等样式 |
| `tools/subagent-smoke.mjs` | 离线冒烟：mock 模型 + 3 路并发 + 父子链接断言 |

### 6.2 运行架构

```
renderer
  └─ window.openfuture.sendMessage(...)
       └─ main/ipc.ts → AgentHost.rpc('send')
            └─ agent-host/index.ts  (utilityProcess)
                 ├─ 主 Pi 会话 (current)  ── assistant turn ──► 调用 delegate_tasks
                 │                                            │
                 │                               SubagentRuntime.run(tasks)
                 │                                 ├─ 子会话 A (SessionManager.create, parentSession)
                 │                                 ├─ 子会话 B
                 │                                 └─ 子会话 C          ← 最多 3 并发
                 │                                            │
                 │                            汇总文本作为工具结果回到主会话
                 └─ AgentStreamEvent { type:'subagent', task } ──► 渲染层进度条
```

- **上下文隔离**：每个子会话独立的 message 列表、独立的 Pi turn 循环；父会话历史不进子会话。
- **工具复用**：子会话继承工作区工具（read/grep/find/ls）、记忆只读工具、web/time 工具；显式剥离 `computer_*`（整机唯一）与 `automation_*`（调度唯一），并且**不注入 `delegate_tasks` 本身**，递归在结构上不可能。
- **模型复用**：同一 `ModelRuntime`、同一 `model`、同一 `thinkingLevel: 'medium'`，避免重复鉴权与模型发现。
- **会话归档**：子会话写入 `<sessionDir>/subagents/*.jsonl`，头部 `parentSession` 指向父会话文件；默认不出现在会话列表，但可用路径回读。
- **取消级联**：`stop()` → `SubagentRuntime.abortAll()` → 每个子会话 `abort()`；`openSession`/`close` 时 `dispose()` 释放全部子会话。

### 6.3 工具契约

```json
{
  "tasks": [
    { "title": "定位记忆写入路径", "prompt": "在 D:\\OpenFuture 中定位……输出文件:行号列表" },
    { "title": "对比两套检索实现", "prompt": "对比 …… 输出 5 条结论" }
  ],
  "timeoutSeconds": 180
}
```

- `tasks`：1–4 个，彼此独立；`title` ≤ 120 字，`prompt` ≤ 20000 字，必须自包含（子 Agent 看不到对话）。
- `timeoutSeconds`：30–600，默认 180。
- 返回值：`子 Agent 执行完成：N 个任务，成功 M，用时 X.Xs` + 每任务分节（标题、状态、耗时、正文、可选会话文件路径），总输出上限 30KB。
- `details` 携带结构化摘要（taskId/outcome/duration/assistantMessages/sessionFile），便于后续 UI 或持久化使用。

### 6.4 预算与上限

| 维度 | 默认 | 上限 | 配置 |
| --- | --- | --- | --- |
| 并发 | 3 | 4 | `OPENFUTURE_SUBAGENT_CONCURRENCY` 或 `SubagentRuntimeOptions.maxConcurrency` |
| 单批任务数 | — | 4 | `SUBAGENT_MAX_TASKS` |
| 单任务超时 | 180s | 600s | 工具参数 `timeoutSeconds` |
| 单任务结果 | 12KB | 60KB | `SubagentRuntimeOptions.maxResultChars` |
| 工具总输出 | 30KB | — | `subagent-tools.ts` |
| 开关 | 开 | — | `OPENFUTURE_SUBAGENTS=0` 关闭 |

### 6.5 事件与 UI

新增 `AgentStreamEvent`：

```ts
| { type: 'subagent'; task: { taskId; title; status: 'queued'|'running'|'tool'|'done'|'failed'|'aborted'|'timeout'; detail?; durationMs? } }
```

- 事件仍带父 `sessionId`（由 main 进程组装），渲染层按 `taskId` upsert；同一轮内 3 个子任务的 `tool`/`done` 更新互不干扰。
- UI 在输入框上方显示「并行子 Agent」条：每行标题 + 当前工具/耗时/错误，完成后保留到下一轮开始或手动关闭。
- 子会话的工具调用**不会**混入父会话的思考链，避免主对话被 3 路流式文本淹没。

## 7. 验证

### 6.6 产品化接线（设置项驱动）

首版用环境变量开关，接入项目设置体系后改为「设置项是唯一入口，环境变量只在直接调用运行时/脚本时生效」：

| 层 | 位置 | 内容 |
| --- | --- | --- |
| 协议 | `src/shared/protocol.ts` | `PublicSettings.subagents`、`PublicSettings.subagentConcurrency`；`SetToolAccessInput` 同步新增两个可选字段 |
| 持久化 | `src/main/settings-store.ts` | `SettingsFile` 新增两字段，默认 `true` / `3`；`getSubagents()`、`setSubagents()`、`getSubagentConcurrency()`（整型 1–4，非法回落 3）、`setSubagentConcurrency()` |
| 宿主环境 | `settings-store.ts#hostEnvironment()` | `OPENFUTURE_SUBAGENTS`、`OPENFUTURE_SUBAGENT_CONCURRENCY`；`AgentHost` 以 `{...process.env, ...environment()}` 启动子进程，因此设置值覆盖 shell 同名变量 |
| IPC | `src/main/ipc.ts` | `parseSetToolAccessInput` 校验布尔/1–4 整数并透传；`toolAccessSet` 落盘后 `host.restart()` |
| 校验提示 | 同一处 | “并行子 Agent 开关必须是布尔值”“子 Agent 并发数必须是 1 到 4 之间的整数” |
| UI | `src/renderer/src/SettingsDialog.tsx` | 「工具与权限」里 PowerShell 之后新增「启用并行子 Agent（delegate_tasks）」勾选框与「子 Agent 并发数」下拉（1–4，关闭时禁用）；与 PowerShell 合并成一次 `setToolAccess` |
| 角色 | `src/agent-host/index.ts` | 子会话 `extensionFactories: [createLiveMemoryExtension('off', undefined, false, agentRole)]`：继承当前会话角色身份，记忆固定关闭，避免并行写记忆 |

补充事实：

- 子会话落在 `<sessionDir>/subagents/*.jsonl`；Pi 的 `SessionManager.list` 只扫描会话目录一层（`session-manager.js` 的 `listSessionsFromDir`），所以子会话不会出现在侧栏会话列表里。
- 子 Agent 的工具集在创建运行时快照那一刻过滤，`delegate_tasks` 在之后才注册，因此子会话结构上拿不到派发工具。
- `stop` 先 `subagents.abortAll()` 再 `session.abort()`，一次停止覆盖整轮 fan-out。

## 8. 与 v0.4 原型的关系

`parallel/multiagent` 的 M0（类型化任务图、角色卡、调度、收件箱）解决的是「**任务如何拆、如何调度、如何审阅**」；本次实现解决的是「**worker 如何真实执行**」。两者是上下层关系：

- 短期：`delegate_tasks` 承担一次性的 fan-out，主 Agent 即规划器。
- 中期：把 M0 的任务图作为可选规划器，图节点直接调用 `SubagentRuntime.run()`，替代其模拟 worker 与 HTTP 桥（19744）。
- 兼容：`TeamRunSummary` / 「协作运行」页仍读旧桥；新运行可写入同一摘要结构，逐步迁移。

## 9. 后续路线

**P1（近期）**

1. **写任务隔离**：`delegate_tasks` 增加 `worktree: true`，在 `git worktree` 副本中运行；结果以 diff 形式回到父会话（对齐 DSH/Claude Code 的 worktree agent）。
2. **后台运行**：`background: true`，子任务完成后以新消息重入父回合（pi-subagents 的做法），用于长任务。
3. **预算细化**：每子任务 token/成本上限、父会话剩余预算传递；超预算标记 `budget-exceeded`。
4. **结果结构化**：子 Agent 通过受控 JSON 输出（如 `{summary, findings[], files[]}`）回传，父 Agent 易聚合，UI 可渲染卡片。
5. **持久化与回放**：把子任务元数据写入父会话 JSONL 的自定义 entry，重开会话能看到历史 fan-out。

**P2（中期）**

6. **角色/模型分工**：`delegate_tasks` 支持 `role`（复用 v0.4 角色卡）与 `model` 覆盖，实现「贵模型规划 + 便宜模型执行」。
7. **workflow 编排**：pipeline / parallel / 循环验证（对齐 DSH `workflow` 工具），带阶段与结构化结果校验。
8. **远程 worker**：A2A/MCP 暴露子 Agent，本地规划 + 远端执行。
9. **可观测性**：每次 fan-out 记录耗时/工具序列/token，落到本地 trace 页。

## 10. 风险与取舍

| 风险 | 影响 | 当前缓解 | 后续 |
| --- | --- | --- | --- |
| 同工作区并发写 | 文件互相覆盖/半成品 | 工具描述明确要求「避免多个子任务同时写同一批文件」；主要为只读任务 | worktree 隔离（P1-1） |
| token 成本放大 | 一次 fan-out = N 份上下文 | 并发 3、单任务 12KB、任务数 ≤ 4；提示词要求「单个任务能直接完成时不要用」 | 预算上限与成本提示 |
| 子 Agent 质量不可控 | 结果跑偏、幻觉 | prompt 必须自包含 + 明确输出格式；父 Agent 汇总时复核 | 结构化输出 + 验证阶段 |
| 事件噪音 | UI 被 3 路流式刷屏 | 子会话只上报状态/工具名，不上报 token 流 | 展开查看子会话详情 |
| 递归失控 | 指数级 fan-out | 子会话工具集不含 `delegate_tasks` | 运行期深度计数（防御性） |
| 共享进程内存 | 一个子会话 OOM 影响全部 | 并发上限 + 超时 + dispose | 独立 worker 进程（重任务） |

## 11. 复现与配置

```bash
# 1) 构建与类型检查（Node 24）
pnpm typecheck

# 2) 离线冒烟（自带 mock，不依赖网络）
node tools/subagent-smoke.mjs

# 3) 桌面端到端（自带 mock + Electron + CDP，断言进度条与汇总回答）
pnpm build && node tools/e2e-subagent.mjs

# 4) 手工体验
pnpm mock-model          # 终端 A：127.0.0.1:8787
pnpm dev                # 终端 B：设置 Base URL=http://127.0.0.1:8787/v1，模型 ID=mock-model
# 对话中输入：「并行调研 src/agent-host 的会话生命周期与工具注册，分别给出结论」
# 期望：出现 delegate_tasks 工具调用 + 「并行子 Agent」进度条 + 汇总回答
```

配置以设置项为准：

| 设置项 | 位置 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用并行子 Agent | 设置 →「工具与权限」勾选框 | 开 | 保存后 `host.restart()`，agent-host 据此注册 `delegate_tasks` |
| 子 Agent 并发数 | 设置 →「工具与权限」下拉 1–4 | 3 | 超过任务数时按任务数开 worker |

设置项经 `settings-store.ts#hostEnvironment()` 注入 agent-host 子进程；`AgentHost` 以 `{...process.env, ...environment()}` 启动，因此**设置值覆盖 shell 同名变量**。下列环境变量仅用于直接调用 `SubagentRuntime`、冒烟脚本或临时调试：

| 变量 | 作用 |
| --- | --- |
| `OPENFUTURE_SUBAGENTS=0` | 关闭子 Agent 能力（不注册工具）；设置项存在时以设置项为准 |
| `OPENFUTURE_SUBAGENT_CONCURRENCY` | 并发数，默认 3，上限 4；同上 |
