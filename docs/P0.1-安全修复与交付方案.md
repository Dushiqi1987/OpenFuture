## 0. 约束与执行顺序

1. 先核对当前源码和现有修改。D:\OpenFuture 没有 Git 元数据，请按文件记录改动，避免用旧副本覆盖现有工作。
2. 先完成 A 的两项安全修复并跑回归，再完成 B 的交互修复。保留当前新会话提示、流式、停止、会话恢复、中文路径和 SQLite 自检。复用 Pi v1.5.0 的工具接口与现有 DTO。
3. 验证只使用临时用户目录、两个 127.0.0.1 模拟端点和合成文件。真实用户的 OpenFuture 配置、会话、密钥和运行实例留给用户。测试服务器不记录完整认证头。
4. 交付独立目录 `D:\OpenFuture\release\p0.1-runnable\OpenFuture.exe` 及其同目录依赖，保留原 `release\win-unpacked`。运行现有构建，将本次输出放入候选的 `resources/app/out`，避免混入旧 renderer 文件。EXE 单文件依赖同目录资源。对候选路径启动并自测。
5. 完成后在本会话回复 `OPENFUTURE_P01_READY`，同时列出修改文件、可启动路径、构建指令、各回归用例实测结果和剩余问题。能自动运行的回归请以最小的方式留在 `tools/`。如果有阻塞，回复 `OPENFUTURE_P01_BLOCKED` 并说明具体失败点、已验证行为及下一步。

## A. 阻断验收的安全修复

### A1. 默认只读工具限定工作区

现有 `src/agent-host/index.ts` 只选择 Pi 的四个内置工具，Pi 把 `cwd` 作为路径解析基准。上一轮在 PowerShell 关闭时，`read` 仍把另一工作区文件和本工作区的合成 `.env` 内容发回了模型。

- 对 `read / grep / find / ls` 全部生效。优先使用 Pi 的公开工具定义和操作注入接口，保留参数、结果结构与限制。任何自动代理能调用的路径都要走同一份权限策略。
- 检查 Windows 绝对路径、相对路径、大小写、其他驱动器、UNC、设备路径和 NTFS alternate data stream。使用规范化的工作区真实路径和基于路径段的边界检查。拒绝词法越界、实际目标越界、链接或 junction 绕行。默认拒绝工作区中敏感项，如 `.env`、`.env.*`、`.git`、`.npmrc`、私钥及凭证文件。目录工具同样过滤条目，递归搜索不进入敏感目录及 reparse point。应用自己的凭证与会话目录也不得由这组工具读取。
- 一次测试至少覆盖项目内普通文件、中文空格路径、兄弟目录绝对路径和 `..`、敏感文件直接读取和递归搜索、跨边界 junction，以及四个工具的拒绝结果。用本地模型验证被拒绝的哨兵内容没有出现在后续模型请求。拒绝时工具结果应说明原因且不回显目标内容。
- PowerShell 是另行启用的高风险命令能力。本任务只验证关闭时模型工具表没有它，并保证修改后的 Key 不通过常规进程环境继承给命令。授权开启时保留现有功能和界面说明，桌面进程隔离不充当操作系统沙箱。

### A2. API Key 与规范化 Base URL 绑定

现有 `SettingsStore` 只持有一个 DPAPI 加密的 Key 文件。切换 Base URL 且 Key 留空时，新端点会收到旧 Key。

- 持久化凭证须包含规范化 Base URL 与 Key，并整体通过 DPAPI 加密。发送前再次验证绑定与当前模型配置一致。相同端点重存可保留 Key。仅末尾斜线、主机大小写等确定等价的地址可视为同一个端点。同 origin 不同路径也按不同 Base URL 处理。
- 换端点且留空时明确要求输入该端点的 Key，或保存成需要重新配置密钥的状态。无论设置保存、进程重启还是文件写入中断，新端点都收不到旧凭证。旧版本只有明文内容为 Key 的加密文件，缺少端点信息。界面提示一次重新录入或显式绑定，避免自动猜测；保留原加密数据至用户成功更新。
- 使用 Pi `ModelRuntime.setRuntimeApiKey()` 等官方 SDK 接口给目标 Agent Host 注入会话凭证。主进程到 Agent Host 的内部通道限用途传递。密钥不出现在 renderer 回参、日志、模型 JSON 明文和派生进程环境。已有环境变量作为开发回退的路径不能使切换端点绕过绑定。未配置 Key 的桌面错误应引导到「模型与密钥」。
- 至少以两个本机 origin 验证 A 同端点编辑保持认证、A→B 留空时 B 不接收 A Key、填写 B Key 后只收到 B Key、重启保持绑定、旧格式在显式确认前不出网。检查键值不进入工具进程环境与日志。实际验证只使用假 Key。
