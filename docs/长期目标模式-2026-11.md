# 长期目标（Goal）模式

> 2026-11-19 · 对应需求：用户希望像其他 agent / harness 一样，给出一个目标后智能体能不断推进、完善，直到目标完成。
> 相关代码：`src/agent-host/goal-tools.ts`、`src/agent-host/index.ts`、`src/main/goal-store.ts`、`src/renderer/src/App.tsx`

## 1. 这个功能解决什么

普通对话是「一问一答」：模型答完，回合结束。真实的长任务（写完一个模块、跑通一条链路、清理一批文档）需要多轮推进，而用户不想每轮手动输入「继续」。

Goal 模式把「目标」变成一个会话级的持久状态：

- 用户写下一个目标（可选最多轮次）；
- 智能体跑完一轮后，宿主自动注入下一轮提示；
- 每轮结束前，智能体用 `update_goal` 记录一句进展；
- 目标完成时标记 `complete`，被外部条件卡住时标记 `blocked`；
- 没有进展（本轮没有任何工具调用、也没有更新进展）时自动暂停，避免空转烧 token。

## 2. 与 Codex / 其他 harness 的对照

| 能力 | Codex | 本项目 |
| --- | --- | --- |
| 目标持久化 | 计划文件 / 会话内计划 | 会话级 `AgentGoal`，落盘 `<userData>/config/goals/<sessionId>.json` |
| 自动续跑 | 由 harness 注入下一步 | 宿主在回合 settle 后注入「第 N/M 轮」提示 |
| 进度记录 | 计划更新 | `update_goal` 工具（`note` + `status`） |
| 终止条件 | 计划完成 / 人工停止 | `complete` / `blocked` / 暂停 / 达到最大轮次 |
| 防跑飞 | 步数或预算限制 | 最大轮次 1–40、无工具自动暂停、失败暂停、重启暂停 |

## 3. 架构

```
renderer (App.tsx)
  ⌖ 目标 pill → goal-setup 面板 → goalStart(objective, maxRounds)
        │
        ▼
main (ipc.ts)
  goalStart → 推送 active credential → host.goalStart()
  goalGet   → host 无会话时从 goal-store 恢复
  goalUpdate/goalClear → 同步 store
        │
        ▼
agent-host (index.ts)
  goal = { id, objective, status, round, maxRounds, note, ... }
  scheduleGoalRound() ──setTimeout──▶ sendMessage(sessionId, goalPrompt())
  sendMessage settle ──▶ afterGoalSettle() ──▶ 暂停 或 下一轮
        │
        ▼
Pi session（同一个会话，上下文连续）
  update_goal(note, status) ──▶ applyGoalUpdate() ──▶ emitGoal() ──▶ renderer goal bar
```

关键点：**目标轮次走的是同一个 Pi session**，所以上下文、文件状态、工具结果都是连续的；宿主只负责「什么时候再发一条提示」。

## 4. 轮次协议

每轮注入的提示词（`goalPrompt()`）：

```
【目标 · 第 N/M 轮】
目标：<objective>
（第一轮：直接开始；后续：「上一轮进度：<note>」）
请继续推进这个目标：先检查已有进展（读文件、运行命令、检索记忆都可以），
再完成下一件具体的事并验证结果；不要只复述计划。
每轮结束前调用 update_goal 写一句 note（不超过 300 字）……
全部达成时 status="complete"；被外部条件卡住时 status="blocked" 并写明原因。
```

`update_goal` 工具：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `note` | string（≤300 字） | 本轮做了什么、验证结果、下一步 |
| `status` | `active` / `paused` / `complete` / `blocked` | 目标状态 |

子 Agent 的工具过滤会排除 `update_goal`，避免子会话篡改父目标。

## 5. 状态机与安全阀

`active → paused / complete / blocked`；`paused → active`（继续）；`complete/blocked` 为终态（可清除）。

| 情况 | 行为 |
| --- | --- |
| 用户点「暂停」或发送中止 | `paused`，note「已按停止暂停」 |
| 模型请求失败 | `paused`，note「本轮模型请求失败，已暂停」 |
| 本轮没有任何工具调用且 note 未变 | `paused`，note「本轮没有工具调用或进度记录，已自动暂停」 |
| 轮次达到 `maxRounds` | `blocked`，note「已达到最大轮次」 |
| 应用重启时目标仍是 `active` | 恢复为 `paused`，note「应用重启后已暂停，点击「继续」恢复」 |
| 新会话（无 Pi session）启动目标 | 宿主抛 `NO_SESSION`，渲染层先建会话再启动 |

`maxRounds` 在 IPC 层夹紧到 1–40，默认 12。

## 6. 持久化与恢复

- 路径：`<userData>/config/goals/<safe sessionId>.json`（`src/main/goal-store.ts`）。
- 写入时机：`goalStart`、`goalUpdate`、宿主每次 `emitGoal`（`src/main/index.ts` 的事件转发）。
- 打开会话时：`ipc.goalGet` 先问运行中的 host；没有则读 store 并 `host.goalSet(saved)`。
- 重启后的 `active` 会被降级为 `paused`，避免崩溃后无限自续。

## 7. UI

- 输入框左侧「⌖ 目标」pill：打开设置面板。
- 设置面板：目标文本、最多轮次（1–40）、开始/取消。
- 目标栏（composer 上方）：`目标 · 第 N/M 轮`、状态徽章（推进中/已暂停/已完成/被阻塞）、目标文本（两行截断）、最近进展、暂停/继续/标记完成/清除。
- 状态从 host 的 `goal` 事件实时更新，切换会话时按会话重新加载。

## 8. 调试中修掉的三个真实缺陷

1. **草稿会话没有 Pi session**：`ensureSessionOpen()` 要求 `activeProject && activeConversation`，草稿时直接返回；目标启动被静默跳过，界面停在「第 0/5 轮」。修复：新增 `openGoalSession()`，草稿时先 `createConversation` 再 `openConversation`，拿到 sessionId 后才启动目标；宿主侧 `goalStart` 增加 `NO_SESSION` 错误。
2. **401 Invalid credential**：目标轮次由宿主内部 `sendMessage` 发出，不经过 `sessionSend` 的 `setCredential`。修复：`goalStart` 与「继续」（`goalUpdate active`）前推送 `store.getActiveCredential()`。
3. **切到草稿后仍显示上一条对话的目标**：`goalGet` 复用共享 host 的 `currentSessionId`，草稿切换瞬间读到旧会话。修复：渲染层 effect 在 `!activeConversationId || !currentSessionId` 时直接 `setGoal(null)`，并把 `currentSessionId` 加入依赖。

## 10. 限制

- 目标按会话保存，不跨设备同步；同一会话串行推进，不并行。
- 目标轮次复用对话上下文，长目标会持续增长 token；需要配合上下文压缩或新建会话。
- 完成/阻塞依赖模型主动调用 `update_goal`；不调用时只能靠「无工具自动暂停」兜底。
- 目标状态不进入 Git 或项目文件，只在本机 userData。
