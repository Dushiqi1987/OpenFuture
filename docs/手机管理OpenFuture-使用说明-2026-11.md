# 手机管理 OpenFuture：装 APK 到用起来（2026-11）

这份文档只讲一件事：**怎么用手机看电脑上的 OpenFuture 项目、会话，并直接发消息。**

不用懂网络，照着做即可。全程大约 5 分钟。

---

## 一、它是什么

手机上装一个 45KB 的小 App（`OpenFuture-phone.apk`），它打开的是**电脑上的 OpenFuture 提供的手机页面**。

```
手机 App（WebView 壳）
      │  同一个 Wi-Fi
      ▼
电脑上的 OpenFuture（端口 8787，只在局域网）
      │
      ├─ 项目列表 / 会话列表 / 历史消息
      └─ 发消息 → Agent 流式回复 / 工具审批 / 停止
```

所以：

- 手机 App 本身不含业务逻辑，**电脑端更新后手机不用重装**；
- 电脑必须开着 OpenFuture，手机才连得上；
- 数据始终在电脑上，手机只是遥控器。

---

## 二、三步用起来

### 第 1 步：电脑端确认服务已开

重启一次 OpenFuture（让新代码生效），然后打开：

**设置 → 手机访问**

这里会显示：

| 项目 | 例子 | 说明 |
| --- | --- | --- |
| 手机访问地址 | `http://192.168.31.32:8787` | 用手机浏览器也能直接打开 |
| 配对码 | `123528` | 6 位数字，10 分钟内有效 |
| 已配对设备 | 空的 / 手机型号 | 换手机或重装才需要重新配对 |

> 第一次运行如果 Windows 弹出防火墙提示，勾选「专用网络」并点「允许访问」。
> 没有弹窗但手机打不开，见文末「常见问题」。

想看更多地址（比如有多个网卡），点「换一个配对码」旁边刷新即可；
如果 8787 被占用，启动前设置环境变量 `OF_REMOTE_PORT=8790`。

### 第 2 步：手机安装 APK

把 `mobile/android/OpenFuture-phone.apk`（v1.3，版本名 1.3.0）传到手机（微信文件传输 / 数据线 / 网盘都行），点击安装。

- Android 会提示「未知来源应用」，允许一次即可；
- 这是调试签名，不是应用商店版本，属正常现象。

### 第 3 步：连电脑

1. 打开 App，输入**电脑上显示的地址**，只填 `IP:端口` 也行（如 `192.168.31.32:8787`），点「连接」；
2. 页面加载出来后，输入**配对码**和给这台手机起的名字（如「我的手机」），点「配对」；
3. 成功后会看到项目列表。点项目 → 点会话 → 看历史、发消息。

配对成功后令牌存在手机里，下次打开 App 直接进项目列表，不用再输码。

> v1.2 起，手机打开会话或发消息时，电脑端窗口会自动切到同一个会话；
> 打开 APK 后如果一直转圈或报错，界面上会直接显示原因（不再是一片黑屏），
> 长按右上角 ⚙ 可以看连接诊断（地址、WebView 版本、最近错误/控制台），并可一键复制。

## 三、手机上能做什么

| 功能 | 说明 |
| --- | --- |
| 项目列表 | 电脑上打开的 OpenFuture 项目，含当前项目标记 |
| 会话列表 | 每个项目的历史会话，显示最后更新时间；没有消息的会话标「草稿」 |
| 历史消息 | 打开会话即加载完整历史（含思考块与工具名摘要） |
| 发消息 | 底部输入框，Enter 发送；忙碌时可继续排队 |
| 流式回复 | Agent 输出逐字显示（SSE，断线自动重连并补发最近事件） |
| 工具审批 | Agent 请求确认时出现卡片：选选项 / 自定义文本 / 跳过 |
| 停止 | 回复中顶部出现「停止」，点一下中断当前回合 |
| 多设备 | 同一台电脑可以配多部手机；令牌存在 `%APPDATA%/OpenFuture/remote/tokens.json` |
| 账户入口 | 右上角 👤：密码或短信验证码登录云平台账号、看余额、退出；地址默认 `http://<电脑IP>:8090` |
| 扫码确认登录 | 电脑端「我的账户 → 手机扫码」出二维码/6 位码；手机扫码会直接打开 App 并确认，也可手填 6 位码 |

扫码登录的前提：电脑端和手机端登录的是**同一个云平台账号**（账号由 `cloud/` 管理，见《商业化链路与手机管理落地》）。二维码内容是 `openfuture://qr?...`，用系统相机/浏览器扫码会唤起 App；如果相机不认自定义 scheme，就在 App 的「账户 → 确认电脑登录」里手填电脑上显示的 6 位码。

不在手机端做的：改设置、装插件、看 diff 文件、管理记忆。这些仍回电脑操作。

## 四、安全边界（自用够，别直接公开）

- **只监听局域网**：服务绑定 `0.0.0.0:8787`，靠路由器 NAT 隔离，不要在公网做端口映射。
- **明文 HTTP**：家庭 Wi-Fi 下可接受；不要在咖啡厅/公司公共 Wi-Fi 长期使用。
- **配对码**：6 位、10 分钟过期、用一次立即作废并自动换新；同一 IP 10 分钟内错 10 次会被临时拒绝。
- **令牌**：32 字节随机数，电脑端只存 SHA-256 摘要；想踢掉所有手机，删除 `tokens.json` 并重启即可。
- **临时关闭**：启动 OpenFuture 前设 `OF_REMOTE=0`，手机入口完全不启动。

## 五、常见问题

**手机打不开地址**

1. 确认手机和电脑连的是同一个 Wi-Fi（不是 5G，也不是访客网络）；
2. Windows 防火墙：设置 → 网络和 Internet → 防火墙 → 允许应用通过防火墙，勾选 OpenFuture 的「专用」；
3. 电脑上有多个 IP（虚拟机、VPN），换一个 `192.168.x.x` 的地址试；
4. 用手机自带浏览器打开同一地址，确认是 App 的问题还是网络的问题。

**配对码总提示不正确**

配对码用一次就换；如果电脑上点过「换一个配对码」，以最新的为准。过期后重新生成。

**安装后打开是黑屏 / 一直转圈**

v1.2 的 APK 会把加载状态和错误直接画在屏幕上：

1. 一直停在「正在连接 …」：地址不通。回到第 1 步核对地址和 Wi-Fi，或先用手机浏览器打开同一地址；
2. 显示「打不开这个地址：…」：看括号里的错误码。`-6`/`-2` 是连不上，`-1` 是未知（多为 WebView 被系统禁用或代理拦截）；
3. 显示「电脑端返回 HTTP …」：电脑端服务异常，看 OpenFuture 控制台日志；
4. 有画面但内容不对：长按右上角 ⚙ →「连接诊断」，把内容复制发出来。

如果装的是旧版（1.0.0）黑屏，直接覆盖安装 v1.3 即可。

**扫码后没反应 / 相机提示无法打开链接**

二维码内容是 `openfuture://qr?...`，部分相机/微信不认自定义 scheme。改用手填路径：电脑「我的账户 → 手机扫码」下面的 6 位确认码，在手机 App 右上角 👤 →「确认电脑登录」里输入即可。

**手机登录账号提示连不上账号服务**

账号服务是 `cloud/` 那套 Java 服务（默认 8090 端口），不是电脑端的 8787。确认它已启动，并且手机填的是电脑的局域网 IP，例如 `http://192.168.31.32:8090`。

**页面能打开但一直「连接中」**

说明页面加载了但接口不通，通常是端口被占用或服务只监听了一半。看 OpenFuture 控制台有没有 `[remote] listening on http://0.0.0.0:8787`。

**发消息提示「先配置模型」**

OpenFuture 电脑端还没选模型或没填 API Key，先在电脑上配好再发。

**审批卡片不出现**

审批只在 Agent 真的调用需要确认的工具时出现；如果电脑端已弹窗并处理，手机上会同步消失。

**想换电脑 / 重装手机**

手机端设置页（右上角 ⚙）里改地址；换手机重新配对一次即可，旧的令牌不影响新设备。

## 六、技术附录

### 接口

| 方法 | 路径 | 鉴权 | 作用 |
| --- | --- | --- | --- |
| GET | `/` `/m` `/index.html` | 否 | 手机页面 |
| GET | `/api/ping` | 否 | 健康检查 |
| POST | `/api/pair` | 配对码 | 换长期令牌，返回可用地址 |
| GET | `/api/events?since=` | 是 | SSE 事件流（续传用 seq） |
| GET | `/api/state` | 是 | 版本、端口、地址 |
| GET | `/api/projects` | 是 | 项目列表 |
| GET/POST | `/api/projects/:id/conversations` | 是 | 会话列表 / 新建会话 |
| POST | `/api/conversations/open` | 是 | 打开会话（返回历史消息与 sessionId） |
| POST | `/api/sessions/:id/messages` | 是 | 发消息 |
| POST | `/api/sessions/:id/stop` | 是 | 停止生成 |
| POST | `/api/prompts/answer` | 是 | 回答 Agent 的提问/审批 |

统一返回 `{"ok":true,"value":...}` 或 `{"ok":false,"error":{"code","message"}}`；
事件帧为 `{"seq":n,"sessionId":"…","event":{…}}`，与桌面端 `agentEvent` 同构。

### 文件

| 文件 | 作用 |
| --- | --- |
| `src/main/remote-host.ts` | HTTP + SSE 服务、配对、令牌、事件缓冲（500 条） |
| `src/main/ipc.ts` | `RemoteBridge`：把手机请求转回既有 IPC handler，复用校验 |
| `src/main/index.ts` | 启动/停止服务，把 Agent 事件广播给手机 |
| `mobile/index.html` | 手机页面（单文件，电脑服务与 APK 共用） |
| `src/renderer/src/MobileAccessPanel.tsx` | 设置里的「手机访问」面板 |
| `mobile/android/` | APK 工程：`MainActivity.java`、清单、图标、构建脚本 |

### 自己构建 APK

```bash
# 1. SDK：只需 build-tools + 一个 platform（无需 Android Studio、无需 Gradle）
#    本机已放在 .android-sdk/sdk（从腾讯镜像下载）
# 2. 构建
ANDROID_HOME=D:/OpenFuture/.android-sdk/sdk bash mobile/android/build-apk.sh
# 产物：mobile/android/OpenFuture-phone.apk（debug 签名）
```

`build-apk.sh` 用 `javac → d8 → aapt2 → zipalign → apksigner` 直接出包；
JDK 17 用 IDEA 自带的 `jbr`（系统 JAVA_HOME 是 Java 8，脚本会强制覆盖）。

### 端口与开关

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |
| `OF_REMOTE_PORT` | `8787` | 手机服务端口 |
| `OF_REMOTE` | 开启 | 设为 `0` 彻底关闭手机访问 |

## 七、已知限制

1. 仅局域网；外网使用需要 Tailscale / 内网穿透（见《商业化链路与手机管理落地》第五节）。
2. 无推送：App 不在前台时不会提醒，回到前台会补拉最近事件。
3. APK 是 WebView 壳，离线打不开；电脑关机即断开。
4. 一台电脑可以配多部手机，但**一个手机同时只连一台电脑**（换地址即切换）。
5. 审批/停止依赖桌面端 Agent 的现有语义，未新增权限模型。
6. 桌面端和手机共用同一个活跃会话：手机打开或发送到别的会话时，电脑端会跟着切过去；反过来在电脑上切会话也会影响手机。同一时刻只保证一个会话在跑。
