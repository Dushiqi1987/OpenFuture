## OF-01 · 阻断 · 撤销证据后，派生笔记仍可出站

- 纠正链路：组合模式下发布一条错误笔记，导入 Pi 会话作为唯一证据，提交并批准纠正 `OF_CORRECT_P32`。撤销来源后，证据搜索零命中，未批准的候选被拒绝，但新会话的模型 system 消息仍包含纠正内容。
- 晋升链路：导入含 `OF_PROMOTED33` 的会话，启动 Dreaming 并发布含该来源的 promote 操作。撤销来源后，检索仍返回派生 note，且新会话 system 消息仍含标记。
- 定位：`src/memory-host/index.ts:1597,1970,2407`。纠正批准和晋升将正文写为笔记，未为具体笔记修订记录证据依赖。活跃 L3 的重建和读取也无法校验这些依赖。
- 修复与通过条件：按笔记修订持久化工作区、来源修订和证据依赖。由同一规则过滤检索、get、L3 和回滚；历史数据无法可靠映射时停用派生正文并提示重审。两条复现都跑通，验证旧会话、新会话、重启、回滚和替换来源时无撤销正文出站，仍有效的独立记忆正常。详见 `docs/P3.2-独立验收与整改.md`。

## OF-02 · 阻断 · 旧纠正覆盖较新手动编辑

- 创建纠正候选 `OF_STALE_APPROVAL_P32`，在审批前手动保存 `OF_MANUAL_NEWER_P32`，然后批准旧候选。实测批准成功，最新正文被覆盖。
- 定位：`src/memory-host/index.ts:2372,2407`。候选没有持久化目标笔记的基线修订，批准时仅校验笔记和证据仍存在。
- 修复与通过条件：创建候选时记录目标修订，在批准事务内对比和条件更新。冲突保留现有正文和投影，旧候选标为需重新预览。验证手动编辑、两候选并发、重复批准和重启后批准。

## OF-03 · 阻断 · 当轮有效 RAG 证据被清理，模型只收到占位符

- 导入含「中文回归标记」的会话。应用本地 `memorySearch` 返回有效证据。让模拟模型调用 `memory_search` 查同一个词，事件显示 tool-end 和 citations。抓取下一次模型请求，tool 消息只包含「历史记忆工具结果已按当前撤销状态清理」。当轮证据未到模型。
- 定位：`src/agent-host/index.ts:155–175`。context 钩子替换所有记忆工具结果，含本轮新鲜、有效的结果。
- 修复与通过条件：给工具结果保留可验证的工作区、条目和修订标识，在出站前按当前状态过滤到条目级。覆盖本轮、后续轮及重启恢复。有效结果的正文和引用应到达模拟模型，撤销后对应条目消失，同批有效条目仍可用，本地原始会话可审计。

## OF-04 · 阻断 · 外部 Wiki vault 缺少工作区绑定

- 仅配置一个合成 vault A，通过 `OPENFUTURE_WIKI_ROOT` 启动同一候选，分别选两个独立工作区。A 的工作区 ID 为 `8167a22d7905441c0a2e939a`，B 为 `74a08b1a44e6aa261800766a`。在组合模式搜索「记忆设计」。未给 B 独立绑定 vault，A 与 B 都返回 `llm-wiki:sources/SRC-2026-11-08-001` 和该 vault 的内容。
- 定位：`src/memory-host/index.ts:109,166,333,1141`。进程级 Wiki 根和客户端被所有工作区搜索复用，外部结果直接并入命中。
- 修复与通过条件：将 vault、客户端、可见页面和缓存按工作区绑定。未绑定工作区保持 Wiki 外部适配关闭。用 A/B 假 vault 验证两边各自只能检索与读取自己绑定且有效的内容。覆盖工作区切换、重启、撤销与旧 ID 访问。
