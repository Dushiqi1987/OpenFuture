## 2. 上游原样复现

### QMD 2.8.3

安装：`.scratch/p1-upstream/qmd`，`@tobilu/qmd@2.8.3`（独立 ESM 项目，`pnpm add --ignore-workspace`）。
pnpm 忽略的构建脚本：`node-llama-cpp`、`tree-sitter-*`；关键词路径不依赖这些原生模块。

结果：
- `createStore({dbPath, config:{collections:{docs:{path,pattern}}}})` 首次索引 3 篇，返回 `indexed:3`。
- 英文：`SQLite`、`offline embedding` 命中。
- 中文：`记忆设计`、`检索`、`中文短词`、`记忆`、`FTS5` 均命中；`记忆系统` 因语料不存在该词而返回空。
- 更新：加入 `MEMORY_UPDATED_SENTINEL` 后 `update()` 返回 `updated:1`，可检索。
- 删除：删除文件后 `update()` 返回 `removed:1`，旧内容不可检索；恢复后重新索引。
- 关闭后仅用 `dbPath` 重开仍可检索。
- 向量检索未启用（无模型下载，`needsEmbedding` 保留）。

脚本：`.scratch/p1-upstream/qmd/repro.mjs`、`repro-zh.mjs`。

## 3. 应用内实现

- `src/memory-host/index.ts`：独立 utilityProcess 内唯一 SQLite 写入点；表 `workspaces`、`workspace_settings`、`sources`、`evidence`、`notes`、`note_versions`、`wiki_pages`、`wiki_versions`、`proposals`、FTS5 `search_index`（trigram）；旧 `memory_notes`/`memory_fts` 仅保留自检。
- workspaceId = 规范化 root 小写后 SHA-256 前 24 位；不同工作区数据不交叉。
- 检索：按 mode 限定 kind；≥3 字符走 FTS5，短词走 LIKE 字面兜底；返回带来源/定位符的引用。
- 来源：导入上限 2 MB，按 origin 撤销旧 active 版并递增 revision，按段落切 evidence。
- Wiki：从 active 来源生成确定性草稿；发布前重新校验来源；撤销来源/页面后不再参与检索。
- L1 笔记：版本表、更新、撤销、FTS 同步。
- 候选：Agent `memory_propose` 只写 pending；桌面端批准后生成 L1 笔记。
- Agent 工具：`memory_search`、`memory_get`、`memory_propose`（RAG/组合）、`wiki_search`、`wiki_get`（Wiki/组合）；全部经 utilityProcess 的受限 tool-request 通道访问，Agent 无 SQLite 直连。
- 引用：memory/wiki 工具结果中的 citation 由 agent-host 提取为 `citations` 事件，渲染层挂到当前 assistant 气泡下方。
- UI：侧栏「记忆库」面板（总览/资料/检索/笔记/Wiki/候选），顶部策略 chip。

## 5. 偏离与限制

1. 运行期未直接嵌入 QMD/Wiki 包：二者在 `.scratch/p1-upstream` 完成原样复现；应用内使用同语义的 SQLite FTS5 检索与确定性 Wiki 草稿。原因是 QMD 的 `node-llama-cpp`/tree-sitter 原生构建在 pnpm 下被忽略，直接打包风险高；这也保证离线可用。后续可在 `memory-host` 增加 adapter 接口切换。
2. 无向量/语义检索：当前为关键词（FTS5 + LIKE 短词兜底）；首次模型下载与联网 embedding 未测。
3. Wiki 生成不调用后台 LLM：按来源摘录生成确定性草稿；语义综合留给 P2 Dreaming。
4. 引用仅实时显示：会话重开时 Pi 消息不含 citations，当前不恢复引用脚注；thinking 块可恢复。
5. 「导入资料」走系统文件选择框，未做自动化点击；导入核心路径已通过 memory-host 直接导入与 UI 数据刷新验证。
6. 打包版未签名、默认 Electron 图标、`asar:false`。
