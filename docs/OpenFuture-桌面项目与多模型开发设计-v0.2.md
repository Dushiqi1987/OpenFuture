# OpenFuture 下一版桌面端开发设计 · 项目、模型与记忆

2026-11-09 · v0.2 需求草案 · Windows 桌面端

本文补充现有 Pi Agent 设计。用户从左侧创建项目，选择一个工作区文件夹和一套记忆策略，再在项目内创建对话。模型凭证集中配置，项目和对话引用已配置的模型。主题、项目树与对话切换由桌面界面提供。

## 1. 桌面页面

界面借鉴 Codex 桌面端的项目与对话导航，延续 OpenFuture 自己的图标、名称和视觉样式。左边定位项目与历史，中间完成对话，右边按需查看引用、记忆或工具活动。[Codex 桌面端说明](https://learn.chatgpt.com/docs/app)

```text
┌──────┬────────────────────┬────────────────────────────────────┐
│ 图标  │ 项目与对话          │ OpenFuture / P3.4 验收    [记忆] [⋯] │
│ 栏   │ [＋ 新建项目]       ├────────────────────────────────────┤
│      │                    │                                    │
│ 项目  │ ▾ OpenFuture  [＋]  │             对话内容                │
│ 搜索  │   P3.4 验收        │                                    │
│ 记忆  │   模型接口调试       │               可选右侧面板          │
│      │ ▸ 遥感实验   [＋]   │                                    │
│      │                    │ ┌────────────────────────────────┐ │
│ 主题  │                    │ │ 输入消息                       │ │
│ 设置  │                    │ │ 百炼 · Qwen3.7 Flash ▾   [发送] │ │
│      │                    │ └────────────────────────────────┘ │
└──────┴────────────────────┴────────────────────────────────────┘
```

| 区域 | 交互 |
|---|---|
| 左侧图标栏 | 上方放「项目」「搜索对话」「项目记忆」，底部放「切换主题」「设置」。图标 18–20 px，按钮热区 36–40 px。悬停约 350 ms 或键盘聚焦时显示中文名称，失焦或按 Esc 收起。选中态同时用背景和可访问状态表达。无项目时，项目记忆入口给出选择项目的提示 |
| 左侧项目树 | 「新建项目」固定在顶部。项目行可展开折叠，右侧「＋」在该项目内新建对话，「⋯」提供项目设置、打开文件夹和归档。对话显示标题、选中态和必要的运行状态。项目的实际路径在项目设置、标题悬浮和「打开文件夹」入口可见 |
| 对话主区 | 顶栏显示项目名和对话名。底部输入框保留模型选择、发送和停止。对话居中并限制阅读宽度，窄窗口允许折叠导航。空项目显示「新建对话」，无需先配置模型即可创建项目和空对话 |
| 右侧面板 | 点击「项目记忆」或对话引用打开。沿用现有记忆总览、资料、检索、笔记、Wiki 和候选。顶部始终显示项目名，切换项目后清空旧面板数据，再载入新项目 |
| 视觉与主题 | 浅色用白底和浅灰侧栏，深色用近黑底和分层灰。按钮、边框、代码块、链接、选区、错误和焦点统一使用语义 CSS 变量。默认跟随系统，可固定为浅色或深色。主题即时生效、重启保留，切换不影响当前流式回复和草稿 |

建议尺寸为图标栏 48 px、项目栏默认 248 px、右侧面板约 360 px。以正常窗口、窄窗口和 125%／150% Windows 缩放检查截断、滚动、菜单、tooltip 和键盘焦点。图标可复用项目现有图标方案，使用 SVG 线性风格，避免依赖字体符号绘制。项目树优先复用现有 React 组件和对话渲染链路。

## 2. 新建项目与对话

1. 用户点击左上角「新建项目」。弹窗第一项为「选择工作区文件夹」，使用 Windows 原生目录选择器。选择后显示完整路径，项目名默认取文件夹名，可改名。
2. 在同一个弹窗选择记忆策略，可同时选择一个已配置的默认模型。模型可以稍后设置。点「创建项目」后，在左侧展开新项目并进入空项目页。
3. 点击项目行的「＋」或空项目页的「新建对话」。新对话归属该项目，继承项目默认模型和当前记忆策略。对话中的模型选择只影响这条对话后续请求。已有回复保留其生成时的供应商和模型标识。
4. 同一实际目录再次被选中时，定位到已有项目。文件夹路径失效时标为「目录不可用」，保留对话浏览，暂停依赖该目录的工具。重新定位前显示旧路径和新路径，由用户确认后重新校验。遇到新目录已被另一项目绑定时拒绝合并。
5. 项目支持改名、折叠和归档。归档仅改变列表可见性，源目录及本地会话可在恢复后继续使用。项目切换保留各对话草稿。首版沿用 Pi 单活跃运行，若仍在生成，允许查看其他历史，开始另一条请求前明确提示先停止现有运行。已有运行的输出继续归原对话。

### 数据归属与生命周期

| 对象 | 建议字段及责任 |
|---|---|
| 项目 `Project` | `id`、`name`、`canonicalRoot`、`memoryPolicy`、`defaultModelRef`、`createdAt`、`archivedAt`。新项目用稳定 ID。项目名称可变，目录绑定由主进程校验 |
| 对话索引 `ProjectConversation` | `projectId`、`piSessionId`、`title`、`modelOverrideRef`、`updatedAt`。正文继续由 Pi JSONL 保存；索引以项目限定访问，模型标记和草稿按对话归属 |
| 活跃运行 `ActiveRun` | `runId`、`projectId`、`conversationId`、`root`、`modelRef`、`policyRevision`。启动时由主进程解析并固定身份，事件带运行与对话标识，避免异步结果串到当前界面 |
| 模型连接与目录 | `ProviderProfile` 保存协议、端点和凭证引用；`ModelEntry` 保存连接下的真实模型 ID、显示名、能力及限制。项目和对话只存引用 |

主进程使用真实路径、Windows 大小写规则和目录分隔边界去重，覆盖大小写、尾部斜杠、盘符根和 junction 别名。打开对话、读取历史、工具调用、导入会话和记忆查询都从主进程项目记录解析目录，校验对话确实归属该项目。异步返回需要检查运行与项目标识。若用户选择互相嵌套的文件夹，明确展示共享的文件访问范围，各自的记忆库仍按项目隔离。

## 3. 项目级记忆

创建时用卡片选一个预设，项目设置中可调整。同一套现有 L0 证据、L1 笔记、L2 Wiki、L3 摘要继续使用。各预设控制何时检索、何时整理和何时注入。

| 创建选项 | 启用的能力 |
|---|---|
| **关闭记忆**（新项目默认） | 可继续正常对话与保存 Pi 历史，暂停记忆检索、采集、后台整理和 L3 注入 |
| **RAG 检索** | 允许显式导入文件或对话证据并按需查证据与笔记。默认 SQLite FTS5，有可用的已配置 QMD 时使用该项目索引 |
| **Wiki 知识库** | 浏览、查询与读取项目内已发布页面。资料生成本地草稿，用户审核后发布。外部 MCP 仅在当前项目绑定并通过隔离验证后启用 |
| **Dreaming 整理** | 手动导入已确认资料，生成待审变更和 L3 预览。经人工发布后注入摘要。自动调度独立开关，默认关闭 |
| **组合模式** | 打开 RAG、Wiki 与 Dreaming。保留独立开关，用户可暂停 L3 注入或后台调度 |

- `MemoryPolicy` 保存 RAG、Wiki、显式会话取证、Dreaming、L3 注入、自动调度等独立开关。创建预设时展示具体开启项。默认只在用户点击导入时收集会话，自动采集需另有功能和明确授权。
- 每项目独立管理资料、会话取证、笔记、候选、Wiki、QMD 索引、L3 投影、版本、调度和预算。沿用现有 SQLite 时，以稳定 `projectId` 或明确的一对一映射绑定旧数据。QMD 目录和外部 Wiki vault／MCP 客户端按项目隔离，未绑定的项目只用本地 Wiki。
- 后台任务按项目 ID 恢复。保存策略时提高策略修订。关闭记忆、撤销来源和禁用 L3 后，下一次出站前必须以最新权限排除失效条目。已有项目切换预设时保留历史内容；重新启用前按当前策略与撤销状态计算可用数据。
- 项目 A 和 B 分别配置 Wiki 和 RAG 时，切换项目、重启、回滚及直接用旧条目 ID 读取都需验证隔离。参考当前 P3.3 整改项，确保有效检索结果可到达模型，已撤销证据的派生条目失效，旧纠正候选无法覆盖新修订。
- L3 面板显示生效版本与「随请求发送给当前模型」提示。项目配置页分别显示当前检索引擎、Wiki 引擎和回退原因。Dreaming 卡片按实际实现说明规则规划和人工审批，完整多阶段模型流程单独跟踪。

## 4. 模型与供应商

### 4.1 用户操作

从左下「设置 → 模型与供应商」进入。点「添加连接」后选择供应商，填写区域或端点及凭证。连接支持模型列表时可刷新和搜索，也可以手动添加模型 ID。保存连接前，用户可点击「测试连接」。显式的「测试对话」只发送固定短句，界面显示实际接收方，测试载荷不含项目文件、会话或记忆。

可给一个供应商建多个连接，例如百炼中国区和国际区。项目设置选默认模型，输入框选择器按「供应商连接 / 模型」显示，区分同名模型。已有项目引用的型号即便从目录查询消失，也保留显示和手工重试入口，标注「列表未返回」或「调用不可用」并保留原因。用户可明确选择替换模型。

### 4.2 首轮适配范围

以下是开发与验收范围。能力由连接、协议和所选模型共同决定。具体型号通过官方列表或手动输入维护，界面不写死会变化的最新型号。

| 批次 | 供应商 | 协议与适配重点 |
|---|---|---|
| 第一批 | **OpenAI GPT** | 优先原生 Responses，复用 Pi 的 `openai-responses`。根据模型能力启用工具、推理摘要和图片输入，保留 Chat Completions 自定义入口。[官方流式协议](https://developers.openai.com/api/docs/guides/streaming-responses) |
| 第一批 | **Anthropic Claude** | 原生 Messages，复用 `anthropic-messages`。处理内容块、工具回传与可用的思考事件。[官方流式协议](https://platform.claude.com/docs/en/build-with-claude/streaming) |
| 第一批 | **Google Gemini** | 原生 Gemini API，复用 `google-generative-ai`。按其结构处理函数调用、函数响应和流式事件。[官方函数调用](https://ai.google.dev/gemini-api/docs/function-calling) |
| 第一批 | **DeepSeek** | 使用其 Chat Completions 兼容接口，校验所选模型的 thinking 开关、工具回传和推理字段。[官方接口](https://api-docs.deepseek.com/api/create-chat-completion/) |
| 第一批 | **阿里百炼 Qwen** | 使用 Chat Completions 兼容接口，端点随区域保存，回归已有 `qwen3.7-flash`，覆盖推理预算与输出上限。[百炼官方接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions) |
| 第一批 | **OpenAI 兼容自定义** | 支持私有网关、反向代理及局域网模型服务。Base URL 包含真实路径前缀，选择认证方式、手动模型 ID 和支持的能力 |
| 第二批 | **Kimi、智谱 GLM、MiniMax** | 各自提供 Chat Completions 预设，处理端点、模型列表、推理参数和工具差异。[Kimi](https://platform.kimi.com/docs/api/chat) · [GLM](https://docs.bigmodel.cn/api-reference/模型-api/对话补全) · [MiniMax](https://platform.minimax.io/docs/api-reference/text-openai-api) |
| 第二批 | **火山方舟豆包、xAI Grok、Mistral** | 提供各自的 Chat Completions 预设，方舟允许按服务要求输入模型 ID 或接入点 ID。[方舟](https://api.volcengine.com/api-explorer/?action=ChatCompletions&groupName=%E5%AF%B9%E8%AF%9D%28Chat%29+API&serviceCode=ark&tab=2&version=2024-01-01) · [xAI](https://docs.x.ai/developers/rest-api-reference/inference/chat-completions) · [Mistral](https://docs.mistral.ai/inference/conversations/chat-completion) |
| 第二批 | **OpenRouter、硅基流动** | OpenAI 兼容聚合网关。保留带命名空间的真实模型 ID，能力按模型识别。展示用户所选网关和模型。[OpenRouter](https://openrouter.ai/docs/api_reference/overview) · [硅基流动](https://docs.siliconflow.cn/docs/api/chat-completions-post) |
| 第二批 | **Ollama、LM Studio** | 本地连接预设，支持各自列模型和手动配置。允许本地服务使用无认证配置，工具与图片能力按加载模型验证。[Ollama](https://docs.ollama.com/api/openai-compatibility) · [LM Studio](https://lmstudio.ai/docs/developer/openai-compat/models) |
| 第二批 | **Azure OpenAI** | 使用资源端点与部署名，首版支持 API Key，复用 Pi 的 Azure Responses 适配并验证请求形态。[Azure Responses](https://learn.microsoft.com/en-us/rest/api/aifoundry/azureopenai/responses) |

### 4.3 适配契约

- 将供应商差异集中在 Pi 的模型注册与兼容参数层。当前固定版本已声明 Responses、Anthropic Messages、Gemini 和 Azure Responses 等 API 类型，逐个验证 Windows 可运行包实际能加载这些实现。UI 统一消费现有的文本增量、思考、工具调用、结束和错误事件。
- 每个模型声明可验证能力。工具能力未知时允许普通对话并提示待验证；已确认不支持工具时避免发送工具 schema，界面说明项目文件工具和记忆工具在该模型上不可用。图片输入、推理开关和预算同样按能力显示。支持停止并保留部分回复。
- 列目录、连接鉴权、真实推理测试分别展示状态。区分 URL 无法访问、401/403、模型 ID 不存在、429、超时、协议不匹配和不支持工具。429 提示冷却信息，重试受限。禁止无提示更换供应商或模型。
- 凭证继续由主进程经 Windows safeStorage 加密，按供应商、协议和规范化端点绑定。端点校验覆盖协议、主机、端口和实际路径前缀。改端点要求重新绑定，跨来源重定向不能带上原凭证。Renderer 只接收配置与状态，不回显原始 Key。日志和测试证据遮蔽认证值。云端预设使用 HTTPS，本地测试和显式本地连接允许 loopback HTTP。
- 会话切模型在下一次运行前生效。保留普通历史，按 Pi 支持情况重新构造兼容的上下文；跨供应商需要安全处理旧思考块、工具调用 ID、模型独占附件和格式。遇到无法安全复用的历史时，给出原因并提供在同项目新建对话的入口。

## 5. 现有数据迁移

现有代码以 `settings.workspace`、单个 `settings.model` 和 Pi 按 cwd 读取会话为入口。记忆表已有工作区身份。迁移利用这些信息建立项目注册表，不要求重写所有会话和记忆记录。代码入口为 `src/main/settings-store.ts`、`src/main/ipc.ts`、`src/agent-host/index.ts` 和 `src/memory-host/index.ts`。

1. 升级先读取旧设置、可识别的 Pi 会话根及已有记忆工作区，展示迁移范围。为能可靠映射的目录创建项目或绑定已有项目。旧当前工作区映射为启动时选中的项目。路径不明的会话放到「待归类」，在明确绑定前只读，严禁靠标题或文件名猜测。
2. 将旧单模型导入为「原有模型」连接并保留真实 ID、端点和参数。确保原正式配置中的百炼 `qwen3.7-flash` 可见；旧 Key 状态显示「需要重新绑定」，让用户在模型页原端点重新输入。保持测试用户目录与正式配置隔离。
3. 以版本号和迁移标记记录结果。保留旧配置备份和原 Pi JSONL。首次迁移、重复运行与中断重试均不得产生重复项目、对话或记忆条目。迁移失败时显示原因并保留可浏览历史，等待重试。
4. 已识别记忆的启用策略按旧项目实际模式映射。无法确定用户曾授权的 L3 注入、会话采集和外部 Wiki 绑定时，列入迁移后的待确认项。保持撤销标记和审核状态。

## 6. 实施顺序与验收

| 批次 | 开发内容 | 必须看到的结果 |
|---|---|---|
| A · 项目壳与主题 | 项目注册、迁移、左侧图标与项目树、对话归属、浅色和深色 | Windows EXE 可启动。新建 A、B，分别选择目录并各建两条对话。切换、关闭重启、目录缺失恢复后，标题、历史、草稿与路径均归属正确。流式过程中切主题和查看其他历史，事件仍回原对话。主题和 tooltip 在键盘操作和 150% 缩放下可用 |
| B · 记忆独立管理 | 创建时选预设、独立面板和配置、QMD/Wiki 隔离、派生记忆撤销回归 | A 开 RAG、B 开 Wiki，用独有标记验证索引、候选、引用、L3、调度和旧 ID 隔离。旧候选冲突与撤销后出站过滤通过。关闭记忆后普通对话可用，下一次请求不带已停用记忆 |
| C · 模型基础 | 多连接、第一批适配、模型选择、旧 Qwen 配置迁移 | 每种协议先用本地模拟端点验收流式、多段工具参数、停止、401/429 及断流。每个供应商分别记录真实连通性、工具测试及是否使用凭证；用隔离目录验证两项目选不同模型、同名模型跨端点隔离、目录缺失时保留已选 ID |
| D · 扩充供应商 | 第二批预设、能力徽标、局域网与本地运行时 | 每个供应商明确已验证能力和未验证项。只有实际通过的接口可标为已验证。Qwen、OpenAI、Claude、Gemini、DeepSeek 和一个本地模型的最小用例进入持续回归 |

最终验收使用新的 Windows 可运行 EXE 及其完整资源目录。交付包含深浅主题截图、迁移记录、双项目隔离证据、各协议验收矩阵、资源哈希和未通过项。现有候选与用户配置可用于独立复验。
