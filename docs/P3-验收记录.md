## 2. 实现

### 2.1 质量门

`src/memory-host/index.ts` 新增 `computeQuality(workspaceId, deleteRatio, contentOverride?)`，返回：

- `duplicateRate`：active L1 笔记的同标题重复率，目标 < 5%；
- `staleRate`：超过 30 天未更新的笔记占比，上限 50%；
- `sourceCoverage`：来源是否可追溯（同名笔记或 active evidence），目标 ≥ 80%；
- `l3Lines / l3Bytes / l3Tokens`：L3 预算 200 行 / 25,000 字节 / 1,500 token；
- `deleteRatio`：上限 25%；
- `verified`：以上 checks 全部通过。

`dreamApply` 在事务内应用 ops 后重新构建 L3，并以 `job.delete_ratio` 与新建内容做质量校验；未通过时抛 `VALIDATION: 质量校验未通过：...` 并回滚整个事务。

### 2.2 预算

- 新表 `dream_usage(workspace_id, day, tokens, PK(workspace_id,day))`；
- 单次 50,000 token、每日 100,000 token（按工作区、UTC 日期）；
- `dreamApply` 事务内检查并累加；超限回滚；
- `dreamQuality` 与 UI 展示今日用量。

### 2.3 空闲调度

- 新表 `dream_schedule(workspace_id PK, auto_dream, interval_minutes, last_run_at)`；
- 默认关闭、间隔 240 分钟；允许 5–1,440 分钟；
- memory-host 在启动后运行 60 秒 tick（测试可设 `OPENFUTURE_AUTO_DREAM_TICK_MS`），满足间隔、无待审任务时生成新的 `review` 任务；
- 只生成待审任务，不自动发布。

### 2.4 正确性修复

- `merge` 后撤销其余重复笔记并移出 FTS，避免 P2 的重复笔记残留。
- `dreamStart` 在构建预览时排除被 merge 的重复目标。
- `dreamApply` 先应用 ops 再构建 L3，使合并后的内容进入摘要。

### 2.5 UI

记忆库 → 总览底部 Dreaming 区新增：

- Verify 质量门卡片：`verified` 徽标、5 项 checks 的 OK/FAIL 与明细、「重新校验」；
- 空闲调度卡片：自动 Dreaming 开关、间隔输入（5–1,440）、保存、今日 tokens / 每日预算、单次预算、上次运行时间。

## 4. 偏离与限制

1. Dreaming planner 仍是确定性规则，不调用 LLM；`phase` 固定 `promote`，未持久化五阶段进度。
2. 质量门是结构性指标（重复、陈旧、覆盖、预算、删除比例），没有 embedding 漂移、语义质量评审或「纠错率 ≥ 70%」；该目标未实现，需接入模型评审后才能宣称。
3. 自动调度只生成 review 任务，是否发布仍需人工确认。
4. 撤销 active 版本仍写空 MEMORY.md，而不是删除文件。
5. 引用仅实时显示，重开会话不恢复 citations。
6. 打包未签名、默认 Electron 图标、`asar:false`；本轮无安装包。
