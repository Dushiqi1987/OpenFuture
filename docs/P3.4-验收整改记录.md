# P3.4 安全整改验收记录（OF-01～OF-05）

日期：2026-11-09

候选目录：`release/p3.4-security-runnable`

## 1. 任务与范围

依据 `docs/P3.3-全量验收与缺陷汇总.md`，对 P3.3 最终候选做独立验收整改：

- OF-01：撤销来源后，已批准纠正与 Dreaming 晋升不得再进入 L3/system。
- OF-02：旧纠正候选不得覆盖审批前的手动新版本。
- OF-03：当轮有效 `memory_search` 结果不得被整体清空；撤销后只移除失效条目。
- OF-04：外部 pi-llm-wiki vault 必须按工作区隔离。
- OF-05：外部 Wiki 命中可通过 `memoryGet`/`wiki_get` 读取正文。

旧候选全部保留；未生成安装包。

## 2. 实现摘要

### OF-01 证据依赖与派生笔记

- `notes.derived`；`note_evidence(note_id, revision, evidence_id, source_id, source_revision, workspace_id)`。
- `noteIsLive(workspaceId, noteId, revision?)` 同时校验笔记、修订、证据、来源及来源修订；`derived=1` 且无依赖时不可见。
- 纠正批准、Dreaming promote/fix/merge 写入依赖；手动 `updateNote` 清除 derived 与旧依赖。
- `loadHit`、`get`、`collectL3Entries`、`l3EntryLive`、`l3ContextFor`、质量检查、Dreaming 入口统一使用 `noteIsLive`。
- `revokeSourceById` / `revokeNote` 立即调用 `refreshActiveProjection`，L3 与 `MEMORY.md` 同步刷新。
- `migrateDerivedNotes` 对历史 approved fix 仅在修订连续时回填依赖；无法映射的旧派生内容按不可用处理。

### OF-02 陈旧纠正候选

- `proposals.target_revision`；创建纠正候选时记录目标修订。
- 批准事务内比较目标修订；不一致时标记 `stale`，不写正文、不 bump revision。
- UI 显示“需重新预览”。

### OF-03 工具结果条目级过滤

- Agent context 钩子不再把全部记忆工具结果替换为占位符。
- 解析 `memory_search` / `memory_get` / `wiki_get` 结果中的条目 ID，向 main 请求当前有效集合；逐条保留、逐条移除。
- 有效条目保留正文与引用；部分失效时重写 `hits` 并清空 `details`；全部失效才使用历史占位符。
- 原始会话 JSONL 不修改，审计仍可回看。

### OF-04/05 Wiki 工作区绑定与详情

- `workspace_wiki(workspace_id, vault_root, mcp_path, updated_at)`；环境变量只作为首次使用的 provisioning 来源，首个使用的工作区获得绑定，其他工作区保持 `off`。
- MCP client、错误、搜索均按工作区维护；未绑定工作区不启动 Wiki 子进程。
- `readWikiPage` 通过绑定工作区的 `wiki_recall` 定位 path，限制在 vault 根内读取，返回正文与 citation；`memoryGet` 与 `wiki_get` 识别 `llm-wiki:` 前缀。

## 4. 验证结果

### OF-01

- sourceA：`src-1f3a7ded-57a3-48db-841e-819ac98852b0`，evidenceA：`ev-4fe0eb3c-3a87-43e5-9ebe-cdc354effb10`。
- baseline Dreaming：`kv-e64c3a10-7c94-4c6a-97ac-594c7c348188`（active）。
- 纠正批准后：note body `OF_CORRECT_P34：纠正后的正文`；L3 `l3HasCorrect:true`，`l3HasPromoted:true`。
- 撤销 sourceA 后：`memoryGet` 为 null；L3 `l3HasCorrect:false`、`l3HasPromoted:false`；搜索不再命中。
- 结论：纠正与 Dreaming 晋升均随来源撤销停止出站。

### OF-02

- 手动更新为 `OF_MANUAL_NEWER_P34` 后批准旧候选，返回 `status:'stale'`；正文保持 `OF_MANUAL_NEWER_P34`。
- 结论：陈旧候选不覆盖新版本。

### OF-03

- 有效轮：`memory_search:OF03_LIVE_EVIDENCE` 的工具结果同时包含证据与同批笔记，无占位符。
- 撤销证据 B 后：工具结果中证据 ID 消失，同批笔记 ID 仍在，未出现整体占位符。
- 再撤销同批笔记后：工具结果无有效条目，出现 `[历史记忆工具结果已按当前撤销状态清理]`。
- 结论：按条目过滤生效，部分有效结果保留，全部失效才清空。

### OF-04

- 同一 profile 中工作区 A 已绑定 Wiki；切换 settings 到工作区 B 后重启。
- 状态：`workspaceId:'c55eafd1cdce10851ceca226'`（与规范路径哈希一致），`wikiEngine:'off'`。
- `memorySearch('记忆设计')` 的 `wikiHits:[]`；`memoryGet('llm-wiki:sources/SRC-2026-11-08-001')` 为 null。
- 结论：未绑定工作区不能看到 A 的 vault。

### OF-05

- 工作区 A 搜索“记忆设计”命中 `llm-wiki:sources/SRC-2026-11-08-001`。
- `memoryGet` 返回 `kind:'wiki'`、`bodyBytes:961`、`hasBody:true`。
- 结论文本与 citation 可读取；未绑定 B 不可读取（见 OF-04）。

## 7. 限制与剩余项

- OF-04 的绑定模型是“首个使用该 env 的工作区拥有绑定”，尚无桌面端逐工作区配置入口；这是安全默认值，不是完整的多 vault UI。
- OF-05 已接通 API 与 `wiki_get`，但未新增独立 Wiki 详情页面。
- QMD 与 pi-llm-wiki 仍是外部可选资源，不随包分发；QMD 仅使用 `searchLex`，未接向量；Wiki 仅读取，未接 ingest。
- 验证使用本地 mock 模型和合成会话，未做真实服务商联调、长时调度、断电恢复和完整人工 UI 走查。
- 未生成安装包，未签名。
